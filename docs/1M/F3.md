## 2. 为什么是「追加」而不是「插入」

历史监督引入的 12,680 个模型接在快照之后，不按 id 或时间混排进去。这样
**前 3,003,759 行仍然精确地是 HF 那份快照**，两个下游因此变简单：
§3.5 的检索侧子采样可以直接用前缀；任何「只看快照内候选」的复算不需要额外的掩码，
按 `mappedID < 3,003,759` 切一刀即可。

追加段内部按规范化 id 排序，是为了确定性——重跑必须给出同一份梯子。

## 3. 追加行的属性从哪来

这 12,680 个模型今天在 HF 上枚举不到，所以没有任何 HF 记录可用。三个量分别处理：

**`size_b` 留空。** 没有 `safetensors.total` 就没有参数量，与快照里那 71.81% 缺失的模型走同一条路：
`size_bucket_id = 0`，描述符里不出现 size 子句。不从名字正则里猜（D-26 在本档同样适用）。

**`family` 从历史图里恢复。** 各历史图存的是 `family_id`，只有配上那张图自己的 `family_vocab` 才有意义，
因此按 D-64 的来源优先级依次读取、先命中者胜。恢复结果：

| 来源 | 恢复到的模型数 |
|---|---|
| `history:modellens_v2` | 12,658 |
| `history:diverse_zoo` | 14 |
| `history:d0_v1_5` | 8 |
| 未能恢复（落 `other`） | 0 |

`family_source` 逐行记下是哪张图给的。恢复出的家族里有 5,942 个是 `Other`——
那是 ModelLens 自己的 Other 桶，不是我们新造的降级。

**`x` 不从历史图复制。** 那些图里有现成的 448 维特征，但 D0 系用的是另一个描述符函数
（HF 富字段版），复制过来会让湖里同时存在两种描述符文本分布，违反约束 2。
F4 用本档唯一的 `model_descriptor` 重算，代价是这批行没有 size 子句。

`layer` 给这批行一个新取值 `no_snapshot_record`，与 `labeled`/`lineage`/`plain` 并列，
表示「不是没有元数据，而是根本没有 HF 记录」。

| 断言 | 结果 |
|---|---|
| 行数等于 快照 + 追加 | 通过（3,003,759 + 12,680） |

| 追加行与快照无交集 | 通过 |

第六条与第八条是合并监督之后才存在的风险：边指向的模型或节点若没有行，
后面的 `edge_index` 会索引到别处，且不会报错。单测 `test_a_supervised_model_missing_from_the_ladder_is_caught`
用一个人造的 ghost 模型钉住了这一条。

## 5. 给 F4 的前置量

梯子本身不算特征，但 `family` 一列已经定了，F4 的 `family_vocab` 规模因此现在就能算。

全湖 3,016,439 行有 **414,478 个不同的 family 字符串**。这个数看着吓人，
是名字规则的长尾造成的：`config.model_type` 只产生 8,447 个不同取值（覆盖 1,061,240 个模型），
名字规则产生 407,561 个（覆盖 1,942,519 个模型）。

按 `FAMILY_MIN_COUNT` 折叠之后：

| 阈值 | 保留的家族数 | 折进 `Other` 的模型占比 |
|---|---|---|
| ≥3 | 40,925 | **13.36%** |
| ≥5 | 23,556 | 15.30% |
| ≥10 | 11,936 | 17.79% |
| ≥50 | 2,410 | 24.00% |

沿用历史各档的 `FAMILY_MIN_COUNT=3`，`Other` 占 13.36%，与 100K 档的 12.78% 基本持平，
`e_fam` 不会塌成一行。`family_vocab` 会有约 4 万行，比 100K 档的约 2,000 行大一个数量级，
checkpoint 与 vocab 的绑定照旧（CLAUDE.md Step 2）。

模型数最多的家族：`llama` 301,004 / `qwen` 186,091 / `bert` 113,380 / `qwen2` 96,941 /
`blockassist` 87,544 / `gemma` 82,557 / `mistral` 72,310。
第五名 `blockassist` 是一个自动化流水线批量产出的家族，
它出现在头部本身就是全量湖构成的一个特征，F8 的分层分析要留意。

追加的 12,680 行里有 52.43% 的 family 字符串在快照里也出现过，
即它们会与快照模型共用同一行 `e_fam` 嵌入；其余多数是 `Other`。
