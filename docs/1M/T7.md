## 1. 为什么是两次前向，而不是一次

| 产物 | 怎么算的 | 干什么用 |
|---|---|---|
| `z_m.npy` / `z_d.npy` | **全图**前向 | 建 HNSW、上线服务。服务时每条边都合法存在 |
| `z_m_eval.npy` / `z_d_eval.npy` | **test-split** 前向 | 🔴 **只有这一份能用来报 `gold@K`** |

held-out 前向里，被查询的那个数据集**看不到自己的 `trained_on` 边**。
这不是洁癖：P4 用全图 `z_d` 打过分，每个 held-out 查询都看见了自己的监督边，
`gold@10` 从 0.42 虚高到 **0.61**。

所以 §10 的 **G-D2 是一个不等式**而不是一句提醒：

```python
assert gold10(z_eval) < gold10(z_full)
```

它断言「无泄漏的那个数应该更小」。两份嵌入一旦被用反，这条会**响**，而不是安静地给出一个更好看的数字。

## 2. 绑定检查：T7 的第一道闸，也是最便宜的一道

checkpoint 里记着它训练时那张图的 sha256。**导出时图对不上就直接停**，在花任何算力之前。

这条不是假想出来的。100K 图在 2026-08-14 为了带上血缘关系类型被重建过
（[`T6more.md`](T6more.md) §1.8 / D-44），`hgraph_100k.pt` 这个**路径上的文件已经换了**：

```text
7fbc3c47ca66227c…   2026-08-11 训练用的那张（现已归档为 hgraph_100k_norel_7fbc3c47.pt）
16f3521482a8efd6…   现行，带 relation_id
```

⇒ **8-11 那批 100K checkpoint 不能拿去对着今天这个路径导出。** 负例实测（本地）：

```text
IncompatibleCheckpoint: checkpoint was trained on graph 00ac2434… but
stage1BuildTransferGraph/hgraph_ml_v2.pt hashes to e6ae2dfe…
Exporting across a rebuild silently mislabels every embedding; …
```

`split_seed` 同理，从 **binding 里读**，不从命令行默认值推——
checkpoint 自己知道它是从哪个划分里 held out 出来的，
用 CLI 默认值重新推一遍，正是「导出时悄悄在训练边上评测」的经典路径。

## 3. 六道门

[`scale1m/export_rung.py`](../../scale1m/export_rung.py) 每次导出都跑完这六条，
结果逐条写进 `EXPORT_MANIFEST.json`；任一条 `ok=false` ⇒ 退出码非零。

| 门 | 判据 | 它拦的是什么 |
|---|---|---|
| **G-D1** | `z_m.shape[0] == expect_n` | 100K 上只给 30,183 个 CORE 模型打分，`gold@10` 纹丝不动，于是「扛住了 83× 干扰」——铁律 3 |
| **G-D2** | `gold10(eval) < gold10(full)` | 用全图嵌入评测 ⇒ 查询看见自己的标签（P4 的 0.42→0.61） |
| **G-D3** | 抽 100 个 `mappedID` 反查 ladder，另**全表**扫一遍 | 行序错位。CLAUDE.md 三大风险之首，**从不自己抛异常** |
| **G-A2** | 分块前向 vs 全图前向 `max\|Δ\| < 1e-5` | `n_id` scatter 写错 ⇒ 行序在导出这一步被打乱 |
| **G-A3** | `five_metric_eval == global_metrics` | 两套 harness 口径漂移 |
| **G-D4** | HNSW `recall@50 ≥ 0.99` | 索引失真；也是 hub 过平滑的第一个报警口 |

两条设计上的讲究：

- **G-D3 在 CORE 档（12k/30k）是 `skip` 而不是 `pass`。** 那两档就是 CORE 图本身、没有 ladder 文件，
  报 `ok` 等于声称做了一次根本没做的检查。只有 100K 有 ladder，那一档才真查。
- **G-D3 的探针是随机位置 + 全表复核**，不是查表头。只查前几行的话，一个越界一位的前缀 bug 能安然通过。

🔴 **`median rank / N` 是核心列，不是 `gold@10`**——它衡量 gold 在池子里的**相对**位置，
是唯一跨 N 可比的量。`vs random = gold@10 / (10/N)`，100K 时随机基线是 `1×10⁻⁴`。

**12K 的三个 split seed**（G-C2 的噪声带，这是它第一次有值）：

| seed | held-out 数据集 | gold@10 | median rank / N |
|---|---|---|---|
| 0 | 517 | | |
| 1 | 496 | | |
| 2 | 539 | | |

> 🔴 **预注册预测照抄 §11.1，先写死免得事后编故事**：100K 落在 **0.10–0.30** 算符合预期；
> **> 0.35**（几乎没掉）⇒ **先查 bug 不是先庆祝**（G-D1 → 铁律 2 的 AUC → G-D2）；

## 5. 本地端到端验证（已完成）

远端排队期间，先在本地把整条链路跑通了一遍——用一个**故意只训 2 epoch** 的 12K checkpoint
（`loss 18.3283 → 16.0864`，与 [`T6GPU.md`](T6GPU.md) §1.1 那次参照运行**逐位相同**，说明本地环境没漂）：

```text
=== T7 EXPORT 12k / R_local_12k ===
  gold@10  held-out 0.2360   full-graph 0.3133   (A-axis uses the held-out one)
  gold@1=0.0619  top3@10=0.3191  root_gold@10=0.2728  gold-gap@10=0.3250
  median gold rank=72/12000 (rank/N=6.000e-03)  vs random=283.2x  queries=517
  HNSW recall@50=0.9909 @ ef=150 p50=0.0301ms
  [PASS] G-D1  [PASS] G-D2  [skip] G-D3  [PASS] G-A2  [PASS] G-A3  [PASS] G-D4
```

三点值得记：

1. **G-D2 的间距是 0.077**（0.2360 vs 0.3133）——泄漏效应真实存在且量级可观。
   这个 2-epoch 模型的 `gold@10=0.236` 远低于 25-epoch 的锚点 0.4159，符合欠训预期，不是异常。
2. **查询数 517**，与 P3 的 517 一致 ⇒ 划分口径没变。
3. **G-A2 通过**：分块前向与全图前向 `max|Δ| < 1e-5`，行序 scatter 是对的。

单元测试 13 条覆盖三道数据门（含「把两份嵌入调换 ⇒ G-D2 必须失败」「表中间交换两行 ⇒ G-D3 必须抓到」
「没有 ladder ⇒ 必须 skip 而不是谎报 pass」）。**全仓 223 passed。**

## 6. 远端执行

作业 **`1511025`**，一次跑完七个 run（同一作业内跑完三档是 §11.2 规则 5 的要求，
跨节点 CPU 差异会污染延迟曲线）：


100K 三个用的是 **`R2rel_*`**（绑 `16f35214…`），不是 8-11 那批——绑定检查会把用错的那种直接拦下。

**一个必须先解决的依赖**：[`T5.md`](T5.md) §9 早就预告过「远端缺 `hnswlib`、`faiss`（T7 要）」，
实测确认两个都不在持久环境里。作业按 T6 探测的同一套办法处理：
staging 到 `/dev/shm` → `pip install hnswlib` → 成功后 `mlf_copy_env` 写回持久环境，
这样后续 T7/T8 不必每次重编。`faiss` 用不上（`build_hnsw` 只依赖 `hnswlib`）。

**排队情况**：整个**可用** GPU 池是满的，不只是 watgpu808——
这个集群按组划分 GRES，我们能用的是 `a2laytongpu`（watgpu708/808，全满）和
`schoolgpu`（watgpu308，8 张里空 4 张，但 **32 个 CPU 全部被占**，`--cpus-per-task=8` 进不去）。
所以**不是 pin 的问题，放开 pin 也没有用**。已按 D-45 把 `--time` 从 1h30 降到 **50 分钟**
（估算：7 次导出 ~25 分钟 + staging + 编 hnswlib），给 backfill 留出机会。

**收集器 `1511028` 已挂在 `afterany:1511025` 上**（`afterany` 不是 `afterok`——失败的证据更要看）。
