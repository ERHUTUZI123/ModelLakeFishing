# 全量档（RF）执行计划：HuggingFace 全库模型湖

本计划在一份 HF 全站快照上端到端建立并评测检索系统。候选池由这份快照定义；
监督则合并全部可信来源——快照自带的 `model-index` 加历史各档积累的测量，逐边标注出处。

前身是 100K 档（[`100k/100kplan.md`](100k/100kplan.md)），它的代码、训练配置、评测协议与工程纪律全部沿用；
监督的组织方式改为多来源合并，理由与代价见 §2.2、§2.3。

候选池：2026-08-18T18:01:49Z 到 18:29:18Z 的 HF 全站快照，3,003,759 个模型（[`F1.md`](F1.md)），
另加 12,680 个只出现在历史监督里、今天已不在 HF 上的模型，**N = 3,016,439**（F2 实测）。
监督为六来源合并，逐边标注出处，实测 **247,803 条边、18,729 个数据集节点、7,859 个合格查询节点**，见 §3.7。

---

## §1 目标与范围

交付一个候选宇宙等于 HF 全站公开模型的检索系统，以及它在这个规模上的三轴数字。

1. 用合并后的多来源监督（快照自带的 `model-index` 加历史各档积累的测量）构造监督与 gold，
   训练归纳式异构 GraphSAGE。
2. 导出全部 3,003,759 个模型的嵌入，建 HNSW 索引。
3. 给出精度、延迟、冷启动三轴的实测值，以及候选池规模变化时的 scaling 曲线。

不做的事：ModelLens 的对照实测（仍为外推）；增量在线更新系统（只做一次性全量快照）；
C 轴若出现塌缩，本档只测量与报告，不做修复实验。

## §2 与既往各档的关系

### 2.1 沿用的部分

- 训练配置 `l1l3b_config()`：L1 全湖 logQ 采样 softmax + L3 native task + `global_n_neg=256` + `batch_size=1024`。
- 模型结构：2 层异构 GraphSAGE，`ModelNodeEncoder` 承担 `[e_name‖e_desc‖e_size‖e_fam]` 拼接，输出 L2 归一化。
- 编码器 `all-MiniLM-L6-v2`，`e_name` 为 seed 42 / 64 维的哈希平均。
- T0 的七项规模化改造（扇出上限、稀疏 M、对比损失采样负例、分块推理、流式打分、诊断可关、HNSW 多线程与 iso-recall），
  其中前两项的误差走向已由 [`100k/T7.5.md`](100k/T7.5.md) 在三档 × 三臂 × 三 seed 上验证。
- F0 补做的图拆件与内存映射（[`scale1m/graph_store.py`](../../scale1m/graph_store.py)）。
- 评测协议：held-out 前向、泄漏门、行序门、iso-recall 延迟协议、三 seed 区间。

### 2.2 候选池与监督分开定义

候选池只由 2026-08-18 的 HF 快照定义：3,003,759 个模型，不掺任何其他来源。这一条不变。

监督则相反，采用**能拿到的全部可信标注**，不限于这份快照。此前各档积累的测量结果——
ModelLens v2 语料、D0/D0.5 的采集、2000 模型系列的消融图、TransferGraph zoo——
都是真实跑出来的 (模型, 数据集, 数值) 记录，把它们弃之不用没有道理。
它们与快照自带的 `model-index` 合并为一份带来源标注的监督集，规则见 §3.7。

这与 100K 档「CORE 逐字节冻结、N 是唯一变量」的做法仍然不同：那时监督是单一外部语料并跨档冻结，
这里监督是多源合并、逐边标注来源，冻结的是合并规则而不是某一份语料。

### 2.3 代价：这不再是单快照封闭世界

引入历史监督换来了大得多的评测集，代价要写在明处，三条：

**湖里会出现快照中不存在的模型。** 历史监督涉及 38,271 个模型，其中 16,713 个（43.7%）
今天已经不能在 HF 上枚举到，多数来自 ModelLens 语料（该来源的存活率只有 44.81%，
其余来源都在 91–100%）。它们仍然进湖作为候选，但每个模型节点带 `in_snapshot` 标志，
A 轴要同时报「全体」与「仅存活模型」两套数字（§3.7）。

**benchmark provenance 从单一来源变成多来源。** 「single-snapshot closed-world construction」
这个说法本档不再成立，方法一节要改写成「多来源、逐边标注、合并规则冻结」。
读者能追到每一条边出自哪次测量，但不能再声称标签与候选来自同一时点。

**不同来源的数值口径不同。** 实测各源的 `edge_attr` 范围：ModelLens v2 与 D0.5 是 [0,1]，
2000 模型系列是 [0,1]，zoo 与 hf1000d 是 [0.60,1.00]。后者显然用了另一套归一化。
因此合并时对每个 (节点, 来源) 组重新做一次 min-max，让所有来源落在同一尺度上（§3.7）。

## §3 实验设计

### 3.1 节点、边与监督

| 元素 | 来源 | 规模 |
|---|---|---|
| 模型节点 | 快照全部记录（`mappedID` 按爬取顺序）加历史监督涉及的湖外模型 | 3,003,759 + 12,680 = **3,016,439** |
| 数据集节点 | 六个来源的数据集节点，跨源按 §3.7 对齐 | **18,729**（其中 7,859 个合格作查询） |
| 监督边 `trained_on` | 六源合并，逐边带 `source`，每节点 200 条上限只在合并后施加一次 | **247,803**（设限前 525,354） |
| 血缘边 `is_base_of` | `baseModels` 优先，`cardData.base_model` 兜底，带 `relation` | 859,056 |
| 数据集相似边 `similar_to` | 数据集特征的 KNN，k=20 | 约 176,000 |

模型节点特征沿用 `[e_name ‖ e_desc ‖ e_size ‖ e_fam]`，其中 `e_desc` 由与历史各档同一个
`model_descriptor(mid, family, size_b)` 生成，`size_b` 只取 `safetensors.total`，`family` 走
`config.model_type`。全湖只有 28.19% 带 size 子句，`e_size` 这一维的信息量低于历史各档，要在报告里写明。

数据集节点特征沿用自 D0 起就没变过的三视图拼接
`x_d (458) = [e_name 64 (哈希, seed 43) ‖ e_card 384 (MiniLM) ‖ e_stats 10]`，
`similar_to` 仍是 `e_card` 上 k=20 的余弦 KNN。`e_card` 的文本由
`d0_build_graph.py::dataset_descriptor()` 生成（名字 + task_categories + tags + description），
本档的输入改为 F1.5 补爬的 HF 数据集卡片，缺卡片时退到该函数已有的名字兜底。
方法与历史各档相同，变的只是卡片文本的来源；`e_stats` 只依赖监督边，照常可算。

### 3.2 监督边的数值口径

`model-index` 的数值不能直接用作边权，四个原因，处理方式各自明确：

指标方向不统一。归一化只对齐量纲，不对齐方向：把 `wer` 或 `loss` 直接 min-max，
数值最大的那个会被当成最好的模型，gold 就是错的。因此在归一化之前先按指标名判定方向，
判定规则维护在一张显式的指标语义表里（`scale1m/metric_semantics.py`），四类处理：

| 类别 | 处理 | 例 |
|---|---|---|
| 已知越大越好 | 直接使用 | accuracy、f1、ndcg@k、recall@k、map、bleu、rouge、pearson、spearman |
| 已知越小越好 | **先翻转方向**（组内归一化后取 `1 − v`）再使用 | wer、cer、loss、perplexity、mae、rmse、mse |
| 方向无法判定 | 保留边，但**不进入 gold 的计算**，也不作为查询集的依据 | 作者自定义的裸名字、无单位的 `score` |
| 语义特殊的 reward | 单独一类，要么单独归一化并单列报告，要么整组排除 | `mean_reward` 及其同族 |

表里没有的指标名一律落到「方向无法判定」这一类，不做猜测。F2 的报告要给出四类各自的记录数与占比，
以及被排除出 gold 的边占监督总量的比例。

指标不可跨数据集比较。出现最多的是 accuracy 96,859、f1 73,033、mean_reward 58,420，其后是一整片
ndcg@k / recall@k。做法是在 (数据集, 任务, 指标) 组内做 min-max 归一化，再对同一个 (模型, 数据集节点)
取该组主指标（组内出现次数最多的指标类型）作为唯一边权。

分组键是 **(dataset, task, full_metric_name)**，三者缺一不可，且指标名取完整形式不做归并：
`ndcg_at_1` 与 `ndcg_at_10` 是两组，`accuracy` 在 `Classification` 与 `text-generation` 下也是两组。
把它们混在一起归一化，等于用一个数据集上不同难度的量去互相定标，得到的 gold 是排序错乱的。
指标名在分组前只做大小写与分隔符的规范化（`ndcg@10`、`NDCG_at_10` → `ndcg_at_10`），
不做语义合并；规范化映射表与语义表（§3.2 第一条）放在同一个文件里。

数值范围不统一。163,999 条数值落在 [0, 100] 之外，主要是 `mean_reward`。组内归一化本身能吸收这一点，
但要先剔除 NaN、无穷与非数值，并把剔除量记进报告。

同一条 (model, dataset, task, metric) 可能有多条记录。去重规则在跑之前固定：
按该四元组分组，取数值的**中位数**；组内条数一并记录。
不取最大值，避免作者重复提交里最好的一次拉高边权；也不允许在看到结果之后改成别的统计量。

### 3.3 强化学习提交

模型数最多的八个数据集里有七个是 RL 玩具环境（`lunarlander-v2` 15,436、`taxi-v3` 7,857、
`frozenlake-v1` 7,510、`cartpole-v1` 5,496 等），任务分布里 `reinforcement-learning` 以 58,600 条居首。
它们是同一门公开课的排行榜提交：同一个环境上成千上万个几乎相同的模型，评价指标是 `mean_reward`。

这类记录对「给数据集选迁移模型」没有信息量，而且会靠边数主导训练信号。
问题不限于 RL：任何一个数据集节点挂着上万条边时，训练就会被那一个生态垄断。因此做法按数据集设限，
而不是只针对 RL 打补丁：

- 每个 (数据集, 任务) 节点最多保留 200 条监督边，超出部分按主指标数值分层抽样，保住数值分布的形状。
  等价的做法是按数据集均衡采样（每个 epoch 从每个数据集节点取同样多的边），两者择一，在 F2 定案。
- RL 组另外排除出评测查询集，因为 `mean_reward` 的语义与其余指标不同（§3.2 第四类）。

F2 实测的实际去向与这条设想不同：`mean_reward` 有 97% 的数值是 `"11.05 +/- 5.90"` 字符串，
解析不出数值，因此 61,294 条记录在第一步就被丢弃，RL 在最终监督里只占 0.24%。
定案是不为该格式加解析器，并在报告里写明「RL 不主导监督」不是排除策略的成效（见 [`F2.md`](F2.md) §5）。

要报的数：设限前后的监督边总数、RL 组在设限前后各自的占比、以及受设限影响的数据集节点数。

### 3.3.1 监督分布必须随 F2 一起报告

仅报总量不足以证明训练没有被单一生态垄断。F2 的报告要按三个维度给出边数与查询数：

| 维度 | 报什么 |
|---|---|
| task | 每个任务的边数、查询数、占比；`reinforcement-learning` 单独一行 |
| dataset | 边数最多的前 20 个数据集，各自的边数、模型数、是否被 200 条上限截断 |
| metric | 每个 full_metric_name 的边数、占比、方向类别（§3.2 的四类之一） |

同时给出设限前后两套，以及基尼系数或 1/HHI 之类的集中度标量各一个。
这一节的用途是让读者自己判断监督是否倾斜，而不是让作者声称它不倾斜。

### 3.4 划分与查询集

评测查询是保留的数据集节点，与历史各档一致：一个数据集节点的全部监督边整体进入 train / val / test，
不做边级别的随机划分，否则查询在训练时就见过自己的标签。

查询集取有 ≥3 条监督边的数据集节点，gold 定义为组内归一化数值最高的模型，
且该边的指标必须属于方向已知的两类（§3.2），数据集名不得是 `unknown`/`custom`/`none` 这类占位名。
占位名节点保留边但不作查询：`unknown / triplet` 一个节点挂着 896 个互不相关语料上的模型，
在其上定义 gold 没有意义（F2 新增，规则版本 `rf-gold-1.1`）。
F2 实测合格查询节点 **7,859** 个（纯快照口径是 2,041，合并后 3.85 倍）。
按 gold 来源拆开：`modellens_v2` 4,681、`hf_model_index` 1,878、`d0_v1_5` 1,143、
`hf_effective` 75、`a_ctrl_2000m` 65、`diverse_zoo` 17。
划分按数据集 id 的属主与基名分组，使 `X/train` 与 `X/test` 这类变体不会跨越划分。
split_seed ∈ {0,1,2}，三 seed 的区间必须一起报。

**≥3 只是最低可用门槛，不是可靠性保证。** 三个候选里的最高分与第二名可能只差噪声，
这种查询上的 gold 排序本身就不稳。F2 合并后四档为 ≥3 7,859、≥5 5,526、≥10 3,450、≥20 1,909，F8 的 A 轴按这四档分别报一遍。
主表深度已在 F2 定案为 ≥3 并写进冻结规则，其余三档作为稳健性附表；
若不同深度给出的结论方向相反，以深度更高的那一档为准并写明。

### 3.5 两条 scaling 曲线

检索侧曲线成本低。模型是归纳式的，`z_m` 只算一次，把索引建在 `z_m` 的随机子集上就能得到任意 N 处的
A 轴与 B 轴数字。子集必须包含全部带监督的模型（gold 候选都在其中），只在无标签模型里均匀抽样，
每个 N 用三个抽样 seed。取 N ∈ {100K, 250K, 500K, 1M, 3,003,759}，共 5 个点。
它回答：同一个训练好的表示下，候选池变大让 gold 掉多少。

训练侧曲线成本高，每个点要重新建图并训练三个 seed。取两个点：一个 500K 的子采样档（兼可行性探针）
与全量档本身。它回答：在更大的图上训练出的表示本身是否更好或更差。

若配额只够一次全量训练，先把 500K 档减到一个 seed，再砍掉它；检索侧曲线不要砍。

### 3.6 受控变量

| | 固定 | 变化 |
|---|---|---|
| 监督边与 gold | 合并后的同一份监督集，各 N 都一样 | — |
| 查询集与划分 | 同一批数据集节点，split_seed ∈ {0,1,2} | — |
| 模型结构与超参 | L1L3b，零改动 | — |
| 编码器 | `all-MiniLM-L6-v2` | — |
| 评测 harness | `scale/global_metrics.py` | — |
| 候选宇宙 N | — | 100K → 250K → 500K → 1M → 全量 |

监督在所有 N 上保持同一份，这一点与历史各档的设计相同：N 是唯一变量，曲线才可解释。
差别在于监督现在是多来源合并的，每条边都带来源标注（§3.7）。

### 3.7 监督的多来源合并

#### 来源清单（实测，2026-08-19）

| 来源 | 图文件 | 模型 | 数据集节点 | 边 | 去重后 | 组内重复 | `edge_attr` 范围 | 模型仍在快照中 |
|---|---|---|---:|---:|---:|---:|---|---|
| `modellens_v2` | `hgraph_ml_v2.pt` | 30,183 | 9,603 | 312,986 | 308,180 | 4,806 | [0, 1] | 44.81% |
| `d0_v1_5` | `hgraph_d05_nocontent.pt` | 10,234 | 1,514 | 55,140 | 55,140 | 0 | [0, 1] | 99.58% |
| `a_ctrl_2000m` | `hgraph_A_ctrl_2000m_xm0_xd0.pt` | 2,000 | 102 | 9,305 | 9,305 | 0 | [0, 1] | 99.95% |
| `hf_effective` | `hgraph_hf_effective_2000m_v2_xm0_xd0.pt` | 2,000 | 96 | 9,403 | 9,403 | 0 | [0, 1] | 99.95% |
| `diverse_zoo` | `hgraph_diverse_xd0.pt` | 306 | 24 | 1,646 | 1,350 | 296 | [0.60, 1.00] | 94.77% |
| `hf_model_index` | 本档快照 | 107,210 | 7,944 | — | 74,346 | — | [0, 1]，组内归一化 | 100% |

两个来源不单独收录，因为它们是上面某一源的子集：`hgraph_zoo_xm0.pt` 的 1,262 对里有 99.52% 落在
`diverse_zoo` 内；`hgraph_hf1000d_2000m` 的 7,056 对**全部**落在 `a_ctrl_2000m` 内
（它自身还带 5,149 条重复边，即历史上记过的那次重复边泄漏）。收录它们只会重复计数。

`hgraph_ml_v2_sub.pt`、`hgraph_d0_v1.pt`、`hgraph_d0_v1_content.pt` 同理不单独收录：
前者是 `modellens_v2` 的 12K 子采样，后两者是 `d0_v1_5` 的早期版本或同一图的 content 变体。

历史五源合并后有 **382,181 条不同的 (模型, 数据集) 对**，若各源完全不重叠应为 391,696 条，
即跨源重叠只有 9,515 对（2.4%）。加上本档的 74,346 条，监督规模的上界约 **45.7 万条边**，
是纯快照口径（74,346）的 6.1 倍，也超过 100K 档单用 ModelLens 时的 312,986 条。

#### 合并规则

**每条边必带来源。** `supervision.parquet` 增列 `source`、`source_metric`、`source_version`，
取值即上表的来源键。任何按监督做的统计、任何 A 轴数字，都要能按 `source` 拆开重报。

**组内重复先消。** 各源自身的重复边按 (模型, 数据集节点) 取中位数，
`modellens_v2` 4,806 条、`diverse_zoo` 296 条、`hf1000d` 5,149 条（该源已不收录）。

**跨源冲突按优先级取一条，并记录冲突。** 优先级 `modellens_v2` > `d0_v1_5` >
`a_ctrl_2000m` > `hf_effective` > `diverse_zoo` > `hf_model_index`：
策展语料是实际跑出来的测量，模型卡片是作者自报，前者更可信。
被覆盖的那条不丢弃，写进 `supervision_conflicts.parquet` 供审计。涉及 9,515 对，占比很小。

**数值重新归一化。** 历史各源只保留了归一化后的权重，且口径不一致（zoo 系是 [0.6, 1.0]）。
因此对每个 (数据集节点, 来源) 组再做一次 min-max，使所有来源与本档的组内归一化落在同一尺度。
这一步不改变组内排序，只对齐尺度；组内取值恒定时置 0.5，与 §3.2 一致。

**方向。** 历史各源的权重在建图时就已经是「越大越好」（normalized accuracy 一类），
因此在 §3.2 的四类之外增加第五类 `curated`：来源已定向，直接使用，且**允许进入 gold**。
这一类不走指标语义表，因为原始指标名在建图时就没有保留下来；
`source_metric` 记为来源自报的字段名或 `unknown_curated`，报告里要写明这一点。

#### 数据集节点的跨源对齐

各源的数据集节点命名互不相同：`modellens_v2` 用 `名字␟任务`、`d0_v1_5` 用 `名字/配置`、
2000 模型系列用裸名字、`diverse_zoo` 用 `glue/qqp` 这种带属主的形式，本档用 `名字\t任务`。
因此上面测到的 9,515 对跨源重叠是**下界**：同一个数据集在两个源里叫不同名字时会被当成两个节点。

对齐按 F1.5 已经做过的两级策略执行：规范化后 id 完全相同则合并；基名相同且在合并后的节点表里唯一
也合并；跨属主与歧义一律不合并。合并前后的节点数、被合并的对数、以及未能对齐的样例都要进 F2 报告。
不做启发式的模糊匹配——把两个不同的数据集并成一个节点，比多留一个节点危害大得多。

#### 湖里的历史模型

16,713 个模型只出现在历史监督里、不在 2026-08-18 的快照中。它们作为候选进湖，
`in_snapshot=false`，`origin` 记录来自哪一源。这带来一条必须履行的报告义务：
A 轴的每个数字都要给出「全体候选」与「仅 `in_snapshot=true` 候选」两套，
前者衡量排序能力，后者回答「今天真的能用上的模型里，检索得怎么样」。
两套数字都是真的，混在一起说才是问题。

## §4 五条实验有效性约束

**约束 1：候选池必须等于声明的 N。** 最可能出现的静默错误是评测只对带监督边的那批模型打分，
指标于是纹丝不动。`--expect-n` 断言与 `MANIFEST.json` 回写照旧；检索侧曲线的每个子采样点各自断言自己的 N，
并断言全部带监督的模型都在索引里。

**约束 2：全湖使用同一个描述符函数。** 所有模型走同一个 `model_descriptor`，字段缺失时按同一规则降级。
本档没有两个总体，所以不再有可分性 AUC 的问题；要报的是全湖描述符的长度分布与各子句的覆盖率。

**约束 3：查询不得看见自己的监督边。** A 轴数字只能用 held-out 前向的 `z_*_eval`，
断言 `gold10(z_eval) < gold10(z_full)`。这条在 P4 上出过事，历史值从 0.42 虚高到 0.61。

**约束 4：gold 构造规则在 F2 结束时冻结，之后不再随结果改动。** 需要一次性定死并写进
`configs/rf_gold_rules.json` 的有：指标语义表与名称规范化映射（§3.2）、分组键、去重统计量、
每节点监督边上限与抽样方式（§3.3）、查询集的最低深度与主表所用深度（§3.4）、划分的分组依据与 seed，
以及监督来源清单、跨源优先级、跨源数据集对齐规则（§3.7）。
该文件带版本号与 SHA-256，写进每次运行的 `MANIFEST.json`；F3 之后任何一项变动都要新起版本号、
重跑受影响的全部阶段，并在报告里并列新旧两套数字。

理由是这些旋钮每一个都能显著改变 `gold@10`，而它们的"正确取值"没有独立判据。
先看结果再调白名单、调 RL 上限、调查询资格，得到的就是一个针对自己指标优化过的基准。
本项目在 v4 阶段已经吃过一次三 seed 假信号的亏，这一条是同一教训的制度化。

**约束 5：每条监督边的来源必须一路带到报告。** `source`、`in_snapshot`、`primary_direction`
三列从 F2 一直带到 F8，A 轴的每个数字都要能按来源拆分、并同时给出「全体候选」与「仅存活候选」两套。
多来源合并的正当性完全建立在可追溯上：读者要能看出某个结论是不是只由某一个来源撑着。

另有一条贯穿全程的工程纪律：`z_m` 的第 i 行必须是 `mappedID == i` 的模型。
行序错位不会抛异常，只会悄悄改写「哪个模型拥有哪一行嵌入」。每一步都有断言。

## §6 预注册预测

在跑之前写下，用于防止事后按数字挑叙述。

本档的监督与查询集与历史各档不同，因此**没有可借用的点估计**。100K 档的 `gold@10 = 0.2071`
是在另一套标签上测的，不能作为本档的预期值，也不能与本档的数字并排比较。
预注册因此只针对形状与量级：

`median rank / N` 是主指标。随机基线是 0.5；若表示有效，它应当落在 10⁻³ 量级或更低。
预注册区间 **[10⁻⁵, 5×10⁻³]**。高于上界说明表示在这个规模上基本失效；低于下界先查泄漏门与候选池断言。

`gold@10` 在 300 万候选池上大概率是一个接近 0 的数：随机基线是 10/N = 3.3×10⁻⁶。
预注册区间 **[0.005, 0.15]**，并要求 `vs random ≥ 10³`。落在区间内按正常结果报告；
高于上界先查三处：候选池是否真是 3,003,759、查询是否看见了自己的监督边、
以及查询集里是否混入了 RL 组（§3.3）。

B 轴。HNSW 的 p50 对 N 的幂律指数在历史三档实测为 0.032，按此外推到 3,003,759 约 0.0178 ms。
全扫 p50 按线性外推约 56.6 ms，加速比约 3,200 倍。若实测 HNSW p50 显著高于 0.03 ms 或 ef 被迫升到三位数，
说明规模开始逼出 ANN 的代价，这本身有价值，按实测报并给出 ef 与 recall 的权衡曲线。

C 轴。预期 `frozen` 层占比 67.59% 左右（由 F1 的分层直接决定），`cold` 层因血缘边完整而显著扩大。
预期 `cold` 仍比 `frozen` 塌得厉害。若 `cold` 反而好于 `frozen`，与 100K 档的结论相反，
先排查血缘边的构建是否正确再下结论。

## §8 风险与未决问题

**监督被少数几个数据集主导。** 最大的数据集有 15,436 个模型，中位数是 1。若不设边数上限，
训练信号会被 RL 排行榜和几个大基准垄断。§3.3 给了上限与分层抽样的做法，
但上限值（每节点 200 条）是拍的，F2 要用实际分布复核一次，并报设限前后的对比。

**三分之二的数据集节点没有真实卡片。** F1.5 实测：查询集口径下 35.50% 的节点有 HF 卡片，
按监督记录加权 59.26%，其余退到名字兜底。这与历史各档同构（那时缺 `desc` 也走同一个兜底），
但比例更高，因此数据集侧表示更弱、`similar_to` 边的质量随之下降。
名字兜底的节点之间会因为名字相似而聚在一起，这是结构性偏差，F5 要按 `card_source` 分层报边分布，
F8 的分析也要按这一列分层。

**血缘 hub 过大。** 119 个父节点各带 1,000 个以上子模型，最大 43,346 个。
扇出上限会截断采样时看到的邻居，但过平滑压力比任何历史档都大。
检测方式是 `lineage_stats.json` 的度数分布与 C 轴的层内余弦；若严重恶化，照实报告并列为下一步实验。

**`size_b` 缺失 71.81%。** 超过七成模型落进 unknown 桶，`e_size` 的信息量低于历史各档。
这不是 bug 而是全量湖的真实构成，但要在报告里写明，并在 C 轴归因时列为混杂因素。

**与历史数字仍然不可直接比。** 监督虽然包含了 `modellens_v2` 的全部边，但查询集、
数据集节点集合、候选池都与 R0/R1/R2 不同，`gold@10` 不能与历史值并排放进一张表。
可以做的是按 `source` 拆分后单独报 `modellens_v2` 那一部分，作为定性参照并写明口径差异。

**多来源带来的三类风险。** 跨源数据集节点可能重名而被误合，或同名不同物而被漏合（§3.7 的对齐只做保守的两级匹配）；
历史源的 `curated` 权重没有保留原始指标名，方向由来源保证而不是由我们的语义表保证；
16,713 个候选今天已不在 HF 上，A 轴必须同时报「全体」与「仅存活」两套。这三条都要在 F8 的报告里单列。

**存储与配额。** 按 §9 估算峰值占用约 20 GB；远端 quota 未确认前不开始大数据上传。
