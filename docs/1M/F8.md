## 1. 结论

四轴全部测完，两条预注册区间命中，一条预注册预期没有复现（§6）。

三个结果值得单独拎出来。

**候选池稀释几乎是免费的。** 候选宇宙从 10 万涨到 301.6 万（30 倍），`gold@10` 从 0.0706 掉到 0.0700，
gold 的绝对排名从 1,736 位移到 1,908 位。也就是说，把三百万个模型放进池子，
挤到 gold 前面的新模型只有一百多个。

**HNSW 对全扫的加速比随 N 线性放大，到全量档是 2,714 倍。** 单次查询 p50 从 10 万档的 0.0175 ms
到全量档的 0.0211 ms，涨了 21%，而候选池涨了 30 倍；全扫从 1.09 ms 涨到 57.26 ms。
p50 对 N 的幂律指数实测 0.036。

**98.5% 的湖塌在一起。** `cold` 与 `frozen` 两层合计占 98.47%，层内平均余弦 0.88–0.93，
有效维度 3.0–3.3（128 维空间里）。最大的几个血缘 hub 更极端：
`qwen/qwen1.5-0.5b` 的 32,534 个子模型两两余弦 0.9863。

## 2. A 轴：精度

### 2.1 三 seed 区间

候选池是全部 3,016,439 个模型，嵌入只用 `z_*_eval`（held-out 前向）。
三个 seed 给的是划分噪声，不是初始化噪声（D-43）。

| | seed 0 | seed 1 | seed 2 | 均值 |
|---|---:|---:|---:|---:|
| `gold@1` | 0.0019 | 0.0078 | 0.0107 | 0.0068 |
| `gold@10` | 0.0700 | 0.0399 | 0.0696 | 0.0598 |
| `top3@10` | 0.1232 | 0.1570 | 0.1147 | 0.1317 |
| `gold-gap@10` | 0.0924 | 0.0703 | 0.0859 | 0.0829 |
| `root_gold@10` | 0.0226 | 0.0328 | 0.0407 | 0.0320 |
| median gold rank | 1,908 | 881 | 3,363 | 2,051 |
| `median rank / N` | 6.33e-4 | 2.92e-4 | 1.11e-3 | 6.80e-4 |
| vs random | 21,103 | 12,034 | 20,992 | 18,043 |
| 查询数 | 1,558 | 1,153 | 1,595 | 1,435 |

核心列是 `median rank / N`（§6）：三个 seed 落在 2.9e-4 到 1.1e-3，
即 gold 的中位排名在候选池的前万分之三到前千分之一。随机基线是 0.5。

seed 之间差得不小（`gold@10` 0.040 到 0.070，median rank 881 到 3,363），
但三个 seed 的查询集本来就不同（1,153 到 1,595 个查询），
所以这是划分带来的区间，不是模型不稳定。报数字时要带区间。

### 2.2 检索侧 scaling 曲线

§3.5 问的是「同一个训练好的表示下，候选池变大让 gold 掉多少」。
用 seed 0 的 `z_m_eval`，把候选池限制到 F7 建的每个子采样宇宙，查询集保持不变
（每个宇宙都含全部 46,146 个带监督与 gold 的行，所以 gold 一定在池子里）。

| N | 抽样 seed | `gold@10` | median gold rank | `rank / N` | vs random |
|---:|---|---:|---:|---:|---:|
| 100,000 | 0 / 1 / 2 | 0.0706 | 1,736 / 1,740 / 1,739 | 1.74e-2 | 706 |
| 250,000 | 0 / 1 / 2 | 0.0706 | 1,756 / 1,757 / 1,752 | 7.02e-3 | 1,765 |
| 500,000 | 0 / 1 / 2 | 0.0706 | 1,776 / 1,778 / 1,772 | 3.55e-3 | 3,530 |
| 1,000,000 | 0 / 1 / 2 | 0.0706 | 1,836 / 1,834 / 1,834 | 1.83e-3 | 7,060 |
| 3,016,439 | 全量 | 0.0700 | 1,908 | 6.33e-4 | 21,103 |

`gold@10` 在 30 倍的候选池上只掉了 0.85%，绝对排名只上移 9.9%。
三个抽样 seed 之间的差别在 ±4 位以内。

这个结果本身解释了它自己：挤在 gold 前面的模型，几乎全是每个宇宙都包含的那 46,146 个带监督模型，
而不是新加进来的无标签长尾。换句话说，**A 轴偏低的原因不是候选池太大，
是带监督的那一小撮里排序还不够准。** 这一条对下一步该往哪使劲是决定性的。

`vs random` 随 N 线性上升（706 → 21,103）正是同一件事的另一种表述：
随机基线是 10/N，而我们的命中率几乎不随 N 变。

### 2.3 两个候选池

`rf-gold-2.0` 要求每个 A 轴数字按全体候选与仅存活候选各报一遍。

| seed | 全体候选 N=3,016,439 | | 仅存活 N=3,003,759 | |
|---|---:|---:|---:|---:|
| | 查询 | `gold@10` | 查询 | `gold@10` |
| 0 | 1,558 | 0.0700 | 1,003 | 0.0229 |
| 1 | 1,153 | 0.0399 | 752 | 0.0532 |
| 2 | 1,595 | 0.0696 | 636 | 0.0613 |

两列不是同一批查询，方向也不一致（一降两升），详见 [`F7.md`](F7.md) §3。
限制候选池会让 35%–60% 的查询失去可比候选，因为那 12,680 个湖外模型正是历史监督覆盖的那批。

### 2.4 观测池内的命中率

同一批查询，把候选限制到该数据集上确实有记录的模型：

| | 均值（三 seed） |
|---|---:|
| `observed_hit1`（挑出已观测模型里最好的那个） | 0.2198 |
| `top3_hit1`（挑到已观测前三之一） | 0.4765 |
| `regret1` | 0.4044 |

这一组不是本档的验收口径，历史上查出过它被泄漏抬高
（见 `top1-global-provenance-fix`），但它与 §2.2 的曲线指向同一件事：
问题在带监督模型之间的排序，不在池子的大小。

## 3. B 轴：延迟

协议按 §11.2：先二分 `ef_search` 使 `recall@50 ≥ 0.99`，然后计时；单线程逐查询，
丢弃 100 次预热后测 1,000 次；全扫基线用同一批嵌入、同一批查询、同一次进程测。
13 个索引在同一个进程里跑完，因为一条斜率里混了硬件差异的曲线不是曲线。

| N | `ef` | `recall@50` | HNSW p50 (ms) | 全扫 p50 (ms) | 加速比 |
|---:|---:|---:|---:|---:|---:|
| 100,000 | 50 | 0.998 | 0.0175–0.0187 | 1.094–1.262 | 59–67× |
| 250,000 | 50 | 0.999 | 0.0199–0.0208 | 4.527–5.216 | 227–251× |
| 500,000 | 50 | 0.998 | 0.0185–0.0214 | 9.439–10.655 | 493–512× |
| 1,000,000 | 50 | 0.998 | 0.0195–0.0210 | 18.388–20.016 | 925–991× |
| 3,016,439 | 50 | 0.9989 | 0.0211 | 57.261 | **2,714×** |

`ef_search` 在每一档都停在下界 50，`recall@50` 全部在 0.998 以上。
HNSW p50 对 N 的幂律指数实测 α = 0.036（历史三档是 0.032），全扫是 α = 1。
候选池涨 30 倍，HNSW 慢 21%，全扫慢 52 倍。

按 §5 F8 给的两条路，这里选的是只报同机测得的加速比：
13 个索引与全扫基线全部在本机同一次运行里测，所以比值内部一致；
绝对毫秒数是笔记本上的数，不能与 100K 档在 watGPU 上的 B 轴并排。

单次查询的 p50 在两次相同的运行之间抖动约 10–18%（例如全量档 0.0201 与 0.0211 ms），
加速比的抖动约 5%（2,871 与 2,714）。这是本机的测量噪声，比值比绝对值稳。

### 吞吐

`knn_query` 每次只带一个查询，而 hnswlib 是在查询批上并行的，
所以逐查询调用时线程数不起作用——第一版报出的「多线程 QPS」因此没有意义
（同一个索引在两次运行里给出 36,177 与 547，后者是内存压力下的伪值）。
改用批量调用后是一条正常的曲线：

| 线程 | 1 | 2 | 4 | 8 | 16 | 24 |
|---|---:|---:|---:|---:|---:|---:|
| QPS（1,558 查询一批，取三次中位数） | 52,655 | 98,894 | 151,444 | 231,525 | 244,546 | 296,417 |

24 个逻辑核拿到 5.6 倍，符合物理核数少于逻辑核数的预期。

## 4. C 轴：冷启动分层

四层按监督度数与血缘定义：`warm` 是 `trained_on` 度数 ≥ 10，`cool` 是 1–9，
`cold` 是度数 0 但有血缘边，`frozen` 是两者皆无。

| 层 | 模型数 | 占比 | 层内平均余弦（三 seed） | 有效维度 |
|---|---:|---:|---|---:|
| `warm` | 2,949 | 0.10% | 0.394 / 0.409 / 0.394 | 3.3–3.9 |
| `cool` | 43,197 | 1.43% | 0.426 / 0.331 / 0.293 | 3.8–4.0 |
| `cold` | 875,314 | 29.02% | 0.882 / 0.912 / 0.931 | 3.0–3.3 |
| `frozen` | 2,094,979 | 69.45% | 0.879 / 0.916 / 0.927 | 2.7–3.4 |

`frozen` 实测 69.45%，§6 按 F1 分层预测 67.59%，对得上。
12,680 个湖外模型全部落在 `warm`(976) 与 `cool`(11,704)，`cold` 与 `frozen` 全在快照内。

### 4.1 与 100K 档的对照

| | 100K `warm` | 100K `cool` | 100K `cold` | 100K `frozen` |
|---|---:|---:|---:|---:|
| 占比 | 5.8% | 24.4% | 19.9% | 50.0% |
| 平均余弦 | 0.553 | 0.626 | 0.935 | 0.815 |
| 有效维度 | 3.16 | 4.49 | 4.12 | 4.34 |

三点：

有监督的两层反而更散开了。`warm` 从 0.553 降到 0.402，`cool` 从 0.626 降到 0.350。
在更大的图上训练，带监督模型之间的区分度是变好的。

**`cold` 比 `frozen` 塌得更厉害这一条没有复现。** 100K 档是 0.935 对 0.815，
本档是 0.908 对 0.907，两层已经分不出来。§6 预写的排查条件是「若 `cold` 反而好于 `frozen`
则先查血缘边构建」——这里不是反转，是持平，所以不触发排查，但预期没有复现要写明。

有效维度两档同量级（3.0–4.5，共 128 维）。所以这个约三维的流形不是全量档新出现的问题，
是这套架构在历史各档上的常态。不能把它当成本档的新发现。

### 4.2 血缘：分离度接近消失

| 档 | 兄弟对平均余弦 | 随机对平均余弦 | 分离度 |
|---|---:|---:|---:|
| 12K | 0.9147 | 0.6066 | 0.3081 |
| 30K | 0.9437 | 0.5979 | 0.3458 |
| 100K | 0.8904 | 0.7401 | 0.1504 |
| 全量（三 seed） | 0.916–0.941 | 0.867–0.914 | 0.028–0.049 |

兄弟对并没有变得更近（0.92–0.94，与历史各档同水平），是随机对变近了：
随机基线从 0.60 升到 0.87–0.91，因为随机抽到的模型有 98.5% 的概率落在
已经塌在一起的 `cold` / `frozen` 里。

最大的几个血缘 hub 单独列出（每个父节点抽 2,000 个子模型，算两两余弦）：

| 父模型 | 子模型数 | 子模型两两余弦 |
|---|---:|---:|
| `black-forest-labs/flux.1-dev` | 43,346 | 0.9342 |
| `qwen/qwen1.5-0.5b` | 32,534 | 0.9863 |
| `qwen/qwen1.5-1.8b` | 30,626 | 0.9866 |
| `google/gemma-2b` | 24,040 | 0.9877 |
| `distilbert/distilbert-base-uncased` | 12,721 | 0.9591 |
| `stabilityai/stable-diffusion-xl-base-1.0` | 10,917 | 0.9369 |
| `google/gemma-7b` | 9,584 | 0.9869 |

这是 CLAUDE.md 点名的三大风险里的第三条（hub 附近过平滑）在全量图上的实测形态。
`ef_search` 已经在下界、`recall@50` 已经 0.998，所以按那份文档的判据，
问题不在索引参数，而在表示：同一个 hub 下的三万个派生模型在嵌入空间里几乎是同一个点。
对比 `flux.1-dev`（0.9342）与 `qwen1.5-0.5b`（0.9863）能看出这不是均匀的——
文本 LLM 家族比扩散模型家族塌得更厉害。

## 8. 实现

新写 [`scale1m/eval_rf.py`](../../scale1m/eval_rf.py)，四个轴各一个独立进程。
决定数字的协议函数——`model_layers`、`layer_geometry`、`sibling_vs_random_cosine`、
`bench_rung`、`fit_curves`——全部从 [`eval_rung.py`](../../scale1m/eval_rung.py) 原样导入，
所以两档是同一套代码量出来的。

没有沿用 `eval_rung.py` 本身的四个原因：它读单文件 `.pt` 图、读 `<run>/exports/`、
索引名是 `hnsw_<rung>.bin`、并且把挤占者按硬编码的 30,183 分成 CORE 与 HALO——
本档没有 CORE。

`eval_rung.bench_rung` 加了一个可选参数 `labels`，默认 `None` 保持历史各档逐位不变。
子采样索引是在大矩阵的一个子集上建的，行 `i` 用原始 `mappedID` 作为标签入库，
所以暴力参照必须用同一套标签空间表达，否则每个 recall 都会读成 0。

新增 [`scale1m/tests/test_eval_rf.py`](../../scale1m/tests/test_eval_rf.py) 六条，
覆盖两处会静默出错的地方：限制候选池时 gold id 要重映射到受限行空间；
子索引文件名要按最后一个 `_s` 切分（`_s` 也出现在 `sub` 里面，
按第一个切会让每个档位都叫 `hnsw`）。仓库合计 313 passed。

## 10. 未决

三件事，按可行性排序。

**hub 过平滑是当前最明确的问题。** `qwen1.5-0.5b` 的 32,534 个子模型两两余弦 0.9863，
而 `ef_search` 已在下界、`recall@50` 已达 0.998，所以这不是索引参数能救的。
按 CLAUDE.md 的判据，下一步是加强对比损失里的同 hub 负样本，或者减一层。
本档 `num_layers` 已经是 1，所以只剩前一条。

A 轴的杠杆不在候选池。§2.2 的曲线说明把池子从 10 万放大到 300 万只让 `gold@10`
掉 0.85%，挤占 gold 的几乎都是那 46,146 个带监督模型。要提精度，
方向是带监督模型之间的排序，不是缩小候选池。

`displacement_quality` 仍需按 D-54 重写。它原本用 `model-index` 的数值审计挤占质量，
而这些数值现在就是监督本身，两者重叠。重写之前这一项没有结论。
