# Y0：提高 3M `gold@10` 的论文外探索

> 状态：实验备忘，暂不纳入论文。本文不改变 X6 的 baseline 设计，也不新增论文贡献。

## 1. 现在知道什么

在 3,016,439 个候选模型上，与后续实验直接相关的结果是：

| 方法 | 三 split seed 平均 `gold@10` | 含义 |
|---|---:|---|
| Frozen MiniLM | 0.0167 | 单纯稠密文本相似度很弱 |
| F6 训练基线 | 0.0598 | 早期 MIPS 结果；未单独分离训练与图结构的作用 |
| BM25 | 0.1016 | 模型名、tags 和 pipeline tag 中有强词法信号 |
| X4-GD | 0.1427 | 改进负样本提议分布后的当前稠密方法 |
| F6 + task 先验 | 0.3009 | 历史任务统计很强，但当前是 serving 端全池重排 |
| X4-GD + task 先验（全池） | 0.3216 | Y2 重算的同口径全池参照 |
| X4-GD/HNSW top-1000 + task 先验 | 0.3031 | Y2 的两阶段方案，保留全池结果约 94.3% |
| node-level 协议下的 F6 + task/兄弟先验 | 0.3536 | 兄弟信号来自 X3 的另一评测协议，不能与 X5/X6 直接并排 |

这些数字只支持三个判断：

1. 当前稠密表示没有充分利用词法匹配。BM25 虽然均值较高，但三 seed 为
   0.1653 / 0.0690 / 0.0706，需要先验证它与稠密结果是否互补。
2. task 先验是目前增益最大的已测信号。Y2 已证明它与 X4-GD 组合后全池可达 0.3216，
   HNSW top-1000 小池重排可达 0.3031，因此不必再用全池扫描作为 serving 实现。
3. X4 证明负样本提议分布很重要，但尚不知道是否值得继续扫描超参或改损失。

## 2. 历史实验队列

> 当前只执行基于 Y2 的 [`Y4.md`](Y4.md)。Y1 与 Y3 暂停，以下内容仅保留为历史备忘，不作为 Y4 的前置条件。

不同时开展原稿中的 A--E 五组方案。先做三个不需要重训的实验，再根据结果选一个 GPU 实验。

### Y1：稠密检索 + BM25 融合

**问题**：BM25 命中的查询，是否正好是 X4-GD 没有找到的查询？

**做法**：复用 X6 已生成的 BM25 与 X4-GD 分数，用 validation query 选定一个简单融合权重，
然后在同一权重下报三个 test seed。实际 serving 可分别取两路 top-K 后合并，不做全池稠密扫描。

**继续条件**：融合的三 seed 均值高于 `max(X4-GD, BM25)`，且不是只靠 seed 0 产生增益。
否则停止所有“把词法特征接入 GNN”的后续方案。

### Y2：HNSW 召回后的小池先验重排

**问题**：能否保留 task 先验的大部分精度，又避免全 3M 候选池的分组重排？

**做法**：X4-GD/HNSW 先召回 top-1000，再只在这 1000 个候选上应用 X2 的 task 先验。
同时报告 `gold@10`、先验重排时间，以及相对于全池先验重排的精度保留率。

**继续条件**：达到全池先验 `gold@10` 的至少 90%。若达不到，说明稠密召回和先验偏好不一致，
不应再花时间调小池重排参数。

**结果**：已通过。最终 HNSW 方案 `gold@10=0.3031`，平均保留全池融合的 94.25%；
end-to-end p50 三 seed 平均为 0.747 ms。详见 [`Y2.md`](Y2.md)。

### Y3：两个零训练诊断

1. 用 X1 的口径重新计算 X4-GD 每个 256-negative step 中带历史监督的负样本数。
2. 重新计算 X4-GD 表示中同 hub 模型的余弦相似度，检查相近模型是否仍然无法区分。

这两个诊断只用来决定是否需要另一轮训练，本身不构成新方法。

### Y4：根据 Y1--Y3 只选一个训练实验

| 观察 | 后续实验 |
|---|---|
| Y1 证明 BM25 与稠密检索明显互补 | 将固定词法特征接入表示，再检查是否超过简单后融合 |
| Y2 有效，但先验重排仍是明显延迟项 | 尝试将 train-only task 先验蒸馏到稠密表示；实测 p50 已低于 1 ms，当前不触发 |

Y2 执行完之后这张表已经不够用了，因为它默认「稠密表示单独的 `gold@10`」是验收量，
而 Y2 测出这个假设在两阶段系统里不成立。改写后的 Y4 判据见 [§6](#6-y4-的走向)。
| Y3 显示有监督负样本仍明显不足 | 只对提议分布做小范围 sweep |
| Y3 显示负样本已充足，但排序仍差 | 比较现有对比损失与一个 listwise 排序损失 |

没有一项诊断支持时，不运行 GPU 实验。不并行实现词法特征、先验蒸馏和新损失。

## 3. 统一口径

- 候选池、split、eligible query 和 gold 完全沿用 X5/X6。
- 所有权重、分组层级和超参只能用 train/validation 选择；test 每个 seed 只在冻结后评测。
- 主指标仍是三 seed `gold@10`，同时保留每个 seed，不只报均值。
- 涉及先验的方法同时报告查询延迟、top-10 模型大小和可行性，防止用大模型偏好换取表面精度。
- 先验蒸馏若被执行，teacher 只能读取训练可见边；蒸馏后再叠加 serving 先验的增益应当变小，否则不能说先验已进入表示。

## 4. 暂时不做

- SPLADE 或其他学习式稀疏检索：需要新架构和新索引，当前没有必要。
- 一次拼接 1,024 维词法特征并重建全部 3M 特征：先等 Y1 证明互补性。
- task 层级、收缩强度和多粒度的大规模 sweep：先完成 Y2 的单一两阶段对照。
- 同时实现多种新损失：Y3 没有指向目标函数时不做。
- 任何跨候选池规模的精度曲线，以及 ModelLens/TransferGraph 的 3M 外推实验。
- 在 X6 NoGraph 三 seed 完成前，不宣称监督训练或图结构的独立增量。

## 6. Y4 的走向

> **本节是已废弃的旧草案，不再执行。** 它依赖 Y1/Y3，并将总体均值差 `0.0273` 设为唯一验收量，
> 均不符合当前决定。唯一有效的 Y4 规格见 [`Y4.md`](Y4.md)。下文仅保留修改历史。

写于 2026-09-04，在 [`Y2.md`](Y2.md) §9 执行完之后。本节只做一件事：把 §2 里那张 Y4 触发表改掉。
不新增实验，不改口径。

### 6.1 Y2 改变了三件事

| 实测 | 出处 |
|---|---|
| 全池融合 0.3216，但只用 task 先验就有 0.2943 | Y2 §9.1 |
| 两阶段 end-to-end p50 平均 0.747 ms，其中重排只占 0.13 ms | Y2 §9.2 |
| 两阶段相对全池的损失 94.25%，且几乎全部来自 top-1000 池截断，HNSW 近似只占 0.07% | Y2 §9.1 |

第一条是本节的全部理由：**在已经有 task 先验的系统里，X4-GD 这份稠密表示的边际价值是 +0.0273**
（0.2943 → 0.3216，+9.3%）。而同一份表示单独看是 0.1427，是 F6 的 2.39 倍。
两个数字都对，但它们回答的不是同一个问题：
`0.1427` 回答「表示单独有多强」，`+0.0273` 回答「表示在我们真正要部署的系统里还剩多少用」。
Y4 是一个训练实验，训练的就是这份表示，所以它必须按第二个数字验收。

### 6.2 由此确定的两条决定

**决定一：Y4 的验收指标从 `gold@10` 改成融合增量 Δ = `G_full_task` − `P_task_only`，现值 0.0273。**
`gold@10` 仍然逐 seed 报告，但它不再是判据。理由是 §6.1：一个把标准 `gold@10` 从 0.1427 抬到 0.20
却让 Δ 不动的实验，对系统没有贡献，只是把先验已经知道的事又学了一遍。
这条同时兼容 Y0 §3 的口径要求（先验相关的方法必须同时报延迟、模型大小与可行性）。

**决定二：先验蒸馏（原 B1）退出 Y4 候选。**
它进入清单时的理由有两条，Y2 把两条都拆了：

- 延迟理由不成立。原论证是先验是 `O(池)` 的、和 B 轴亚线性主张互相拆台；
  实测 p50 0.747 ms，重排只占其中 0.13 ms。没有要解决的延迟问题。
- 更要命的是方向问题。蒸馏的定义就是让稠密分数逼近先验分数，也就是**主动把 Δ 推向 0**。
  它会让标准 `gold@10` 好看（学生像老师），同时让这份表示在融合系统里更没用。
  按决定一的判据，蒸馏是唯一一条可以确定不通过的候选。

保留一个复活条件：如果之后要论证「先验不可用时系统还能用」（新 task 组、冷启动、
X1 §1 里 seed 2 那种大任务族整根落在 test 侧的划分），蒸馏才重新有意义，
但那时它的验收指标是先验盲区上的 `gold@10`，不是 Δ。

### 6.3 Y4 应该打哪里

按 Δ 的定义，稠密表示唯一还值钱的地方是**先验够不着的查询**。三条已有实测圈出了这块地方：

- X1 §1：同任务通道的天花板三 seed 均值 0.5905，即约四成查询的 gold 根本不在同任务池里，
  先验对它们结构性无能为力。
- X1 §1：seed 2 的同任务池中位大小只有 6 个模型（seed 0 是 1,245），天花板 0.4307。
  先验的强度取决于划分，弱划分正是表示该顶上的时候。
- Y2 §9.1：稠密 top-1000 只对 51.88% 的查询含 gold；但两阶段能拿到的上限就是全池融合的 0.3216，
  所以**召回工程最多只值 +0.0182**（0.3034 → 0.3216）。这是一条明确的止损线：Y4 不做召回工程。

所以 Y4 的目标不是「让稠密更准」，是「让稠密在先验盲区上更准」，
这也意味着 Y4 的报告必须分层，不能只报三 seed 均值。分层键用先验覆盖度，
零成本、从已有 sidecar 直接算：查询所属 task 组在训练可见边上的模型数，分 0 / 1–9 / 10–99 / ≥100 四档。
按 X1 的 seed 差异，这个分层同时替我们处理了 Y0 §3 那条「不只报均值」的要求。

### 6.4 改写后的 Y4 触发表

| Y1/Y3 的观察 | Y4 做什么 | 判据 |
|---|---|---|
| Y1 显示 BM25 与 X4-GD 互补，且互补主要发生在先验覆盖低的分层 | 固定词法哈希特征接入 `x_m`/`x_d`，三 seed | Δ 高于 0.0273，且增量集中在 0 / 1–9 两档 |
| Y1 显示 BM25 与 X4-GD 互补，但只在先验覆盖高的分层 | 不做训练实验，把 BM25 作为第三路召回并入 Y2 的两阶段 | 无（工程改动，不占 GPU） |
| Y3 显示带监督负样本仍然明显不足 | 只对提议分布做小范围 sweep，三 seed | Δ 上升；单纯 `gold@10` 上升而 Δ 不动则判否 |
| Y3 显示负样本已足够但排序仍差 | listwise 损失，且**负样本池取自先验盲区**，不取自同任务池 | Δ 上升，且低覆盖分层的 `gold@10` 上升 |
| 以上都不成立 | 不跑 GPU 实验 | — |

第四行改了一个细节：Y0 §2 原本写 listwise 的候选池是「同任务池」，
那正好是先验已经覆盖的部分，会再次把训练推向 Δ→0。负样本池必须取先验盲区。

### 6.5 Y4 之前要补的零成本测量

三项，都不需要 GPU，应当挂在 Y1 与 Y3 上顺带做完，否则 §6.4 的表无法判读：

1. 按 §6.3 的四档分层重算 Y2 的 `P_task_only` / `G_full_task` / `G_exact1000_task`，
   给出 Δ 的分层版本。这是 Y4 全部判据的分母。
2. Y1 的 BM25 融合按同一分层报告，并报 BM25 与 dense 各自的 `gold_recall@1000` 及两者并集的召回。
   并集那一项只是为了确认 §6.3 那条 +0.0182 止损线，不是为了做召回工程。
3. Y3 的两个诊断（负样本带监督比例、同 hub 余弦）照原样，不改。

如果第 1 项算出来 Δ 在所有分层上都接近 0——也就是稠密表示在任何一档上都没有超出先验的贡献——
那么 Y4 不应该是一个训练实验，而应该是一份「在这个 benchmark 上，学到的表示相对历史统计没有增量」
的负结果记录。这个结局与 X1 §6、X2 §1 的警告一致，必须允许它发生。
