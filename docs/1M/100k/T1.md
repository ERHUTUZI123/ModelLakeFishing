# T1：watGPU 环境打通操作指南

本文只说明如何完成 `100kplan.md` 的 T1，不替执行者登录、安装、上传或提交作业。目标不是开始 100K 正式训练，而是把 watGPU 的访问、存储、Python/CUDA 环境、最小项目链路和 Slurm batch 链路全部验证并留痕。

完成后应有两个交付物：

1. `docs/1M/S0/WATGPU_ENV.md`：保存登录节点和计算节点的原始探测输出、最终路径、partition/account、GPU/CUDA/Python 信息。
2. 一个成功的 tiny Slurm 作业及一个 12K/2-epoch R0 冒烟记录，包括日志、Slurm job ID、最终状态和关键输出。

> 官方规则：watGPU 登录节点不是计算节点。登录节点只用于 Git、轻量检查、提交和监控；训练、GPU 检查、批量处理和评测必须在 Slurm 分配的计算节点运行。正式作业优先用 `sbatch`，交互式 `salloc` 只用于调试。

## 2. 登录节点探测并保存原始输出

登录成功后只运行轻量命令。先建立探测日志：

```bash
STAMP=$(date -u +%Y%m%dT%H%M%SZ)
PROBE_DIR="$HOME/mlf_t1_probe"
mkdir -p "$PROBE_DIR"
LOGIN_LOG="$PROBE_DIR/login_${STAMP}.txt"

{
  echo "UTC_TIME=$(date -u --iso-8601=seconds)"
  echo "USER=$USER"
  whoami
  hostname
  pwd
  id
  python --version
  git --version
  conda --version 2>/dev/null || true
  module avail 2>&1 | head -50
  nvcc --version 2>/dev/null || echo "no nvcc in login-node PATH"
  echo "--- resources ---"
  sresources
  sinfo -o "%P %N %G %m %c %l"
  scontrol show node | grep -E "NodeName|Gres|RealMemory|CPUTot"
  echo "--- my Slurm access ---"
  sacctmgr show assoc where user="$USER" format=Account,Partition,GrpTRES,MaxJobs,MaxWall
  squeue -u "$USER"
  sshare -U
  echo "--- storage ---"
  quota -s 2>/dev/null || true
  df -h "$HOME"
  env | grep -E '^(WORK|SCRATCH|TMPDIR)=' || true
  for p in "${WORK:-}" "${SCRATCH:-}"; do
    [ -n "$p" ] && [ -e "$p" ] && df -h "$p"
  done
  du -sh "$HOME" 2>/dev/null || true
} 2>&1 | tee "$LOGIN_LOG"
```

需要从输出中确定并记录：

- 可用 partition。官方文档说明 `ALL` 对所有用户开放；`SCHOOL` 和研究组 partition 是否可用仍以 `sacctmgr`/实测为准。
- 是否需要 `--account=<ACCOUNT>`。只有确认了 account 才填写；不确定时不要猜。
- 可用 GPU 的 GRES/constraint 名称。不要因为计划目标是 A100/H100 就擅自写一个集群不认识的 constraint。
- home quota、真正的大文件目录及其清理策略。不要预设 `/scratch`、`/work` 或 `$WORK` 一定存在。

登录节点上不要运行 `nvidia-smi`、PyTorch CUDA 测试或项目训练。

## 8. 提交 tiny `sbatch`

交互冒烟通过后，才验证 batch 链路。在远端 `$MLF_CODE_ROOT` 新建 `mlf_t1_smoke.sbatch`，内容如下：

```bash
#!/bin/bash
#SBATCH --job-name=mlf_t1_smoke
#SBATCH --partition=ALL
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
#SBATCH --time=00:20:00
#SBATCH --output=logs/%x-%j.out
#SBATCH --error=logs/%x-%j.err

set -euo pipefail

source "$HOME/.config/modellake/watgpu.env"
source "$MLF_ENV_ROOT/bin/activate"
cd "$MLF_CODE_ROOT"

RUN_DIR="$MLF_OUTPUT_ROOT/T1_tiny_${SLURM_JOB_ID}"
mkdir -p "$RUN_DIR/metadata"

{
  date -u --iso-8601=seconds
  hostname
  git -C "$MLF_PROJECT_ROOT" rev-parse HEAD
  git -C "$MLF_PROJECT_ROOT" status --short
  python --version
  python -m pip check
  nvidia-smi
} > "$RUN_DIR/metadata/environment.txt" 2>&1

python - <<'PY'
import json
import os
import torch

run_dir = os.path.join(os.environ["MLF_OUTPUT_ROOT"],
                       "T1_tiny_" + os.environ["SLURM_JOB_ID"])
torch.manual_seed(0)
model = torch.nn.Sequential(
    torch.nn.Linear(32, 64), torch.nn.ReLU(), torch.nn.Linear(64, 1)
).cuda()
opt = torch.optim.Adam(model.parameters(), lr=1e-2)
x = torch.randn(128, 32, device="cuda")
target = torch.randn(128, 1, device="cuda")
losses = []
for _ in range(8):
    opt.zero_grad(set_to_none=True)
    loss = torch.nn.functional.mse_loss(model(x), target)
    loss.backward()
    opt.step()
    losses.append(float(loss))
assert all(torch.isfinite(torch.tensor(losses)))
assert losses[-1] < losses[0]

ckpt = os.path.join(run_dir, "tiny.pt")
torch.save(model.state_dict(), ckpt)
clone = torch.nn.Sequential(
    torch.nn.Linear(32, 64), torch.nn.ReLU(), torch.nn.Linear(64, 1)
).cuda()
clone.load_state_dict(torch.load(ckpt, map_location="cuda", weights_only=True))
with torch.no_grad():
    assert torch.allclose(model(x), clone(x))
with open(os.path.join(run_dir, "result.json"), "w") as f:
    json.dump({"loss_first": losses[0], "loss_last": losses[-1],
               "cuda": torch.version.cuda,
               "gpu": torch.cuda.get_device_name(0)}, f, indent=2)
print("T1 tiny smoke PASS", losses[0], "->", losses[-1])
PY

python -m pytest \
  ModelLakeFishing/stage2TrainGraphSAGE/tests/test_t0_scale.py \
  -k "train_loop_with_all_switches or five_metric_gpu_cpu_rank_parity" -q
```

如果实测 partition 不是 `ALL`，修改脚本中的 `#SBATCH --partition`。如果确认需要 account，增加：

```bash
#SBATCH --account=<CONFIRMED_ACCOUNT>
```

注意 `#SBATCH` 参数由 Slurm 在 shell 启动前解析，不能依赖脚本内 `source` 后才出现的变量。

提交与记录 job ID：

```bash
source "$HOME/.config/modellake/watgpu.env"
cd "$MLF_CODE_ROOT"
mkdir -p logs
JOB_ID=$(sbatch --parsable mlf_t1_smoke.sbatch)
echo "$JOB_ID" | tee "$HOME/mlf_t1_probe/tiny_job_id.txt"
```

监控不要高频轮询：

```bash

scontrol show job -dd "$JOB_ID"
tail -f "logs/mlf_t1_smoke-${JOB_ID}.out"
```

作业结束后：

```bash

cat "logs/mlf_t1_smoke-${JOB_ID}.out"
cat "logs/mlf_t1_smoke-${JOB_ID}.err"
cat "$MLF_OUTPUT_ROOT/T1_tiny_${JOB_ID}/result.json"
```

只有 `State=COMPLETED`、`ExitCode=0:0`、日志中出现 `T1 tiny smoke PASS`、测试通过且 `result.json` 可解析，才算 batch 链路通过。

## 9. 12K/2-epoch R0 冒烟

这是 T1 最后一个项目级门，不是 100K 正式运行。先确认两份图 SHA 和 corpus 22/22 均通过，再创建独立 sbatch。资源建议为 1 GPU、4 CPU、32G、1 小时。

核心命令应从 `$MLF_CODE_ROOT` 执行：

```bash
python -m ModelLakeFishing.scale.export_ours \
  --graph "$MLF_DATA_ROOT/graphs/hgraph_ml_v2_sub.pt" \
  --seed 0 \
  --epochs 2 \
  --tag T1_R0_smoke \
  --fanout \
  --sparse-M \
  --contrast-n-neg 256 \
  --chunked-infer 50000 \
  --stream-scores \
  --hnsw-threads 4
```

把这条命令放入与第 8 节相同结构的 sbatch 脚本中，并把资源改成：

```bash
#SBATCH --job-name=mlf_t1_r0
#SBATCH --partition=ALL
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=4
#SBATCH --mem=32G
#SBATCH --time=01:00:00
#SBATCH --output=logs/%x-%j.out
```

## 常见故障

### `Host key verification failed`

先核对管理员提供的主机指纹，再检查 `ssh-keygen -F watgpu.cs.uwaterloo.ca`。不要禁用检查。

### 作业长时间 `PENDING`

```bash
squeue -j <JOB_ID> -o "%.18i %.9P %.20j %.8T %.10M %.30R"
scontrol show job -dd <JOB_ID>
```

查看 `Reason`。常见原因是资源请求过窄、account/partition 不匹配或当前无可用 GPU。不要靠高频 `squeue` 轮询。

### `torch.cuda.is_available()` 为 false

先确认命令真的在 Slurm 分配的计算节点内、`nvidia-smi` 正常，再检查 PyTorch 是否安装了 CUDA wheel。不要用系统 `nvcc` 是否存在作为唯一判据；最终以 PyTorch CUDA runtime 和实际张量运算为准。

### `No space left on device` / quota 超限

检查 `quota -s`、`df -h`、`du -sh "$HF_HOME" "$PIP_CACHE_DIR" "$MLF_OUTPUT_ROOT"`。确认大容量目录和清理政策后再迁移 cache。不要在未检查绝对路径时做递归删除。

### 作业 `COMPLETED` 但没有科学产物

Slurm 的 `COMPLETED` 只表示进程退出码为 0。还要检查 JSON 可解析、checkpoint/embedding/index 存在、无 NaN/Inf、commit/config 与预期一致。

### 作业被 preempt/requeue

官方文档说明 `ALL`/`SCHOOL` 作业可能被更高优先级作业抢占并重新排队。实验身份使用独立 logical run ID，不要只依赖可能变化的 Slurm job ID；检查 `sacct` 状态并保留完整日志。
