# Z2：置信度条件化的 query-level 自适应融合

> 状态：已执行（2026-09-06）。依据 [`Z0.md`](Z0.md) 方向二；未通过预注册判据，实际系统不变，停止进入方向三。

## 1. 唯一问题与直接控制组

Z1 的最强常数配置为 `raw, beta=8, shrink=20`。把排序无关的公共缩放去掉后，它等价于：

```text
g0 = 8 / 9
score(q,m) = (1-g0) * dense(q,m) + g0 * prior20(q,m)
```

Z2 只问：由查询时可见的历史支持度和分数分布估计 `g(q)`，能否稳定超过这个常数控制组。超过当前生产配置
`raw, beta=1, shrink=5` 但未超过 Z1 常数配置，不算方向二成立。

## 2. 数据边界

- 直接复用 Z1 的 validation-safe exact top-1000 与 test HNSW top-1000 池，不重跑表示或 ANN。
- 每个 seed 独立拟合 gate；seed `s` 只读取自己的 validation pool 及 train-visible history，不跨 seed 合并样本或参数。
- validation 历史只含该 seed 的 train-root edges；test 特征只含对应的 train+val sidecar。任何 test edge 都不得进入特征或拟合。
- gate 拟合只使用 gold 位于 top-1000 的 validation queries；所有指标仍在完整 eligible-query 集合上计算。
- `fit` 阶段不得打开 `test_pool_s*.npz`。最终系数、scaler、支持度分层阈值和输入摘要写入冻结清单后，`test` 才能运行一次。

## 3. 固定 gate

```text
g(q) = sigmoid(logit(8/9) + delta + sum_j w_j * x_j(q)),  w_j >= 0
score(q,m) = (1-g(q)) * dense(q,m) + g(q) * prior20(q,m)
```

全部特征都定向为“数值越大，越应相信 prior”，并按 validation 的 median/IQR 缩放：

1. `log_task_models`：该 task 在可见历史中的不同模型数；
2. `log_task_roots`：该 task 在可见历史中的不同数据集 root 数；
3. `pool_supported_fraction`：top-1000 中具有 task/model 历史的比例；
4. `log_top10_support_mean`：prior top-10 候选历史支持数的平均 `log1p(count)`；
5. `prior_std`；
6. `prior_top1_top10_margin`；
7. `negative_dense_top1_top10_margin`：dense 越平坦，该量越大。

不使用 task ID、dataset ID、模型属性、test 标签或人工分层 lookup。单调约束防止模型从少量 validation queries
记忆反直觉规则。

## 4. 固定拟合目标

以 Z1 常数控制组的 top-50 错误候选作为 hard negatives，排除 gold 和 empirical top-3，优化 gold-vs-negative
pairwise logistic loss。每个查询先对其 negatives 求均值，再跨查询求均值，避免历史候选多的查询占更高权重。

固定参数如下，不做网格搜索：

```text
temperature = 0.05
L2(lambda) = 1.0                 # 对 delta 和 w，锚定 g0
hard negatives = 50
optimizer = L-BFGS-B
five-fold validation = GroupKFold(root)
```

五折 OOF 只诊断 gate 是否能泛化；随后每个 seed 用自己的全部 validation queries 重拟合一次并冻结。test 后不允许
换 loss、特征、正则、阈值或 gate。

## 5. 必报结果与判据

必须报告：

- validation OOF 和 test 的逐 seed `gold@1`、`gold@10`、`top3@10`；
- 相对 Z1 常数控制组及生产配置的逐查询 rescue/harm；
- `g(q)` 分布、逐 seed 系数、训练 query 数；
- 按 validation 的 task-model-support 三分位数冻结的 test 分层结果；
- top-10 `size_b` 中位数/缺失率及 gate+重排、端到端 p50/p95。

只有同时满足以下条件，才说方向二成立：

1. validation OOF 平均 `gold@10` 严格超过常数控制组；
2. test 三 seed 均不低于常数控制组，且每个 seed `rescue > harm`；
3. test 平均 `gold@10` 严格超过 Z1 的 0.3142；
4. 端到端 p50 <= 5 ms、p95 <= 10 ms；
5. top-10 非缺失 `size_b` 中位数不超过常数控制组 2 倍，缺失率不增加超过 5 个百分点。

失败时保留当前实际系统 `HNSW K=1000 + raw beta=1, shrink=5 task prior`，并停止进入方向三。

## 7. 执行结果

### 7.1 冻结与无泄漏检查

三个 gate 分别只用本 seed 的 validation-safe pool 和 train-visible history 拟合；训练样本数为
171 / 398 / 352，即 gold 实际位于 top-1000 的 validation queries。root-grouped 五折 OOF 完成后，
scaler、系数和支持度三分位阈值先写入 `Z2_FROZEN.json`，其冻结前 SHA-256 为：

```text
2f92b93533c00ea748ae4baac499dac4ccf6ecc3cd476455930c56b764cf11f6
```

测试阶段验证该哈希后才读取 test pools。validation query root 未进入 train history，test query root 未进入
train+val history；三个 seed 之间没有共享训练样本、scaler、系数或阈值。

### 7.2 Validation OOF

| 排序 | seed 0 | seed 1 | seed 2 | 三 seed 均值 `gold@10` |
|---|---:|---:|---:|---:|
| 当前生产配置 | 0.1527 | 0.4599 | 0.1735 | 0.2620 |
| Z1 常数控制组 | 0.1643 | 0.5949 | 0.2008 | 0.3200 |
| adaptive gate OOF | 0.1671 | 0.5912 | 0.2022 | 0.3202 |

adaptive 相对常数控制组的 rescue/harm 分别为 `1/0`、`0/2`、`1/0`。因此按三 seed 非加权均值，
OOF 形式上提高了 0.00020；但按查询计数，两个 rescue 与两个 harm 正好相抵，且 seed 1 已出现退化。

最终 gate 没有学出强烈的条件化规则。三个 test gate 的中位数为 0.8547 / 0.8871 / 0.8634，仍靠近
常数 `g0=0.8889`。`pool_supported_fraction`、`log_top10_support_mean` 和 `prior_std` 的三个 seed
系数全部被单调约束优化器压到零；支持度和 margin 只产生很小修正。

### 7.3 冻结后的 3M HNSW 测试

| 排序 | seed 0 | seed 1 | seed 2 | 三 seed 均值 `gold@10` |
|---|---:|---:|---:|---:|
| 当前生产配置：beta=1, k=5 | 0.3279 | 0.3388 | 0.2427 | 0.3031 |
| Z1 常数控制组：beta=8, k=20 | 0.3496 | 0.3333 | 0.2595 | 0.3142 |
| confidence-adaptive gate | 0.3503 | 0.3333 | 0.2608 | 0.3148 |

| seed | queries | adaptive vs fixed rescue | harm | net | `gold@10` 变化 |
|---:|---:|---:|---:|---:|---:|
| 0 | 1,476 | 3 | 2 | +1 | +0.00068 |
| 1 | 1,101 | 0 | 0 | 0 | 0 |
| 2 | 1,545 | 2 | 0 | +2 | +0.00129 |

三个 seed 合计只增加 3 个 hit（4,122 个 eligible queries 中的 0.073%）。三 seed 平均补充指标为：

| 排序 | `gold@1` | `top3@10` |
|---|---:|---:|
| 当前生产配置 | 0.1274 | 0.3737 |
| Z1 常数控制组 | 0.1356 | 0.3687 |
| confidence-adaptive gate | 0.1360 | 0.3696 |

按 validation task-model-support 三分位数冻结后，seed 0 只在 mid 组净增加 1 个 hit，seed 2 只在
low 组净增加 2 个，seed 1 三层都没有变化；没有出现可复现的“某种支持度下 gate 有效”的分层规律。

### 7.4 延迟、大小与判定

gate 加 top-1000 重排的 p50/p95（ms）为 `0.078/0.096`、`0.078/0.101`、`0.078/0.109`；
端到端 p50/p95 为 `0.482/0.828`、`1.037/1.975`、`0.675/1.251`。top-10 非缺失模型大小
中位数与常数控制组基本相同，缺失率变化均小于 0.1 个百分点。

| 预注册 gate | 结果 |
|---|---|
| validation OOF 均值超过常数控制组 | 通过（+0.00020） |
| test 三 seed 均不下降 | 通过 |
| test 每个 seed 均 rescue > harm | **失败**（seed 1：0 = 0） |
| test 均值超过 Z1 的 0.3142 | 通过（0.3148） |
| 延迟预算 | 通过 |
| 模型大小偏置检查 | 通过 |
| Z1 常数与生产配置精确复现 | 通过 |

方向二因此判定为 **不成立**。虽然平均值有 0.00066 的正变化，但 gate 几乎退化为常数权重，增量只有三个
查询且没有跨 seed、支持度分层的稳定证据。最简结论是：在当前 benchmark、X4-GD 表示和 task prior 下，
这些 query-level 支持度/置信度特征不足以稳定改善固定融合。实际系统继续保持
`HNSW K=1000 + raw beta=1, shrink=5 task prior`，不启动方向三 residual ranker。
