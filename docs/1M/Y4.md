# Y4：Y2 两阶段检索的候选池规模曲线

> 状态：初始实验于 2026-09-05 执行；最终复跑与系统取舍于 2026-09-06 回填。Y4 只以 [`Y2.md`](Y2.md) 的结果为起点；Y1、Y3 暂不考虑。
> 本实验不修改 X6 baseline，不引入新模型、新训练目标或新论文贡献。

## 1. 问题

Y2 已经确定：

| 方法 | 三 split seed 平均 `gold@10` |
|---|---:|
| X4-GD | 0.1427 |
| 全池 task prior only | 0.2943 |
| 全池 X4-GD + task prior | 0.3216 |
| exact top-1000 + task prior | 0.3034 |
| HNSW top-1000 + task prior | 0.3031 |

HNSW top-1000 相对 exact top-1000 保留 99.93% 的 `gold@10`，但 exact top-1000 相对全池融合只保留
94.32%。因此 Y2 剩下的可定位问题不是 HNSW 近似误差，也不是先验重排延迟，而是固定 `K=1000`
造成的候选池截断。

Y4 只回答一个问题：

> 将第一阶段候选池从 1,000 扩大到 2,000、5,000 和 10,000，能否在保持毫秒级查询的同时，
> 稳定恢复一部分 `0.3034 -> 0.3216` 的全池融合差距？

这是一项现有系统的精度—延迟测量，不是训练实验。Y2 本身不能判断应该换负采样、损失函数还是输入特征，
所以 Y4 不预设这些干预。

## 2. 固定口径

除候选池大小外，所有设置沿用 Y2：

| 项 | 固定值 |
|---|---|
| 候选池 | 3,016,439 个模型 |
| 表示 | X4-GD 的 `z_m_eval` / `z_d_eval` |
| 查询 | X5 `gold_eligible`；seed 0/1/2 为 1,476 / 1,101 / 1,545 |
| 第一阶段 | cosine/IP exact 或现有 Y2 HNSW 索引 |
| 候选池大小 | `K in {1000, 2000, 5000, 10000}`，执行前冻结，不追加点 |
| 第二阶段分数 | `(cos + 1) / 2 + task_prior` |
| task prior | shrink `k=5`，`beta=1`，每个 test query 只读取对应 seed 的 train+val 边 |
| 排名 | 分数降序；并列时沿用 X6 的固定、标签无关 tie-break |
| 主指标 | 三 seed 的 `gold@10`，逐 seed 和均值同时报告 |

`G_full_task`、`G_exact1000_task` 和 `G_hnsw1000_task` 必须精确复现 Y2，分别作为固定融合器的全池参照、
池截断基线和当前部署基线。`P_task_only=0.2943` 只保留为解释性参照，不把均值差
`G_full_task - P_task_only` 设为 Y4 的独立验收指标。

## 3. 实验设计

### Y4-A：一次 exact 扫描生成嵌套候选池

对每个 seed 只扫描一次全 3M 模型并保留 exact top-10000。`K=1000/2000/5000` 直接取该结果的前缀，
不得分别扫描或生成不嵌套的候选池。对每个 K 仅在池内应用冻结的 task prior，得到
`G_exact{K}_task`。

该阶段报告：

- `gold@10`、`gold@1`、`top3@10`；
- gold 是否进入第一阶段 top-K；
- 相对 `G_exact1000_task` 的逐查询 rescue/harm；
- 相对全池融合的保留率与池截断差距恢复率。

对 seed `s`，定义：

```text
gap_s = G_full_task_s - G_exact1000_task_s
gap_closed_s(K) = (G_exactK_task_s - G_exact1000_task_s) / gap_s
```

不截断 `gap_closed` 到 `[0,1]`；负值和超过 1 都按原值报告。三个 seed 先分别计算，再取均值。

逐查询配对使用最终 `gold@10` 命中状态：

```text
rescue: K=1000 未命中，K>1000 命中
harm:   K=1000 命中，K>1000 未命中
net:    rescue - harm
```

同时报告原始查询数和比例，避免只用两个总体均值之差解释增益。

### Y4-B：在同一组 K 上运行 HNSW

复用 Y2 已建成的三个 HNSW 索引。对每个 K，`ef_search` 只按 exact top-K 的 ID recall 选择，候选为：

```text
K, ceil(1.5K), 2K, 3K, 5K
```

取第一个达到 `recall@K >= 0.99` 的值；不得按 test `gold@10` 选择 `ef_search`。达到门槛后应用与
Y4-A 完全相同的 task prior 和 tie-break，得到 `G_hnsw{K}_task`。

每个 K、每个 seed 分开报告：

- `recall@K` 与选中的 `ef_search`；
- `gold@10` 及相对 exact 同 K 的差值；
- HNSW 查询、task-prior 重排和两者合计的检索阶段 p50/p95；
- 相对 HNSW top-1000 的 rescue/harm；
- 索引大小不重复计入，因为所有 K 复用同一索引。

延迟沿用 Y2 的测法：索引预热后，单查询、单 HNSW 查询线程；不计索引加载与构建时间。

## 4. 结果判定

Y4 不因某个 K 的均值最大就宣布成功。按以下顺序判定：

1. **correctness gate**：所有 K、所有 seed 的 HNSW `recall@K >= 0.99`，且 K=1000 精确复现 Y2。
2. **池规模是否有用**：若 `K=10000` 的 exact `gap_closed` 三 seed 均非负、均值至少为 0.50，
   则“扩大候选池能恢复至少一半现有池截断差距”成立；否则不成立。
3. **近似检索是否保留增益**：对 exact 增益为正的 K，HNSW 相对 K=1000 的增益至少保留 90%，
   且三个 seed 的 HNSW `gold@10` 均不得低于各自的 K=1000 基线。
4. **是否形成新的运行点**：在满足前述门槛的 K 中，只有 HNSW 加重排的检索阶段 p50 不超过 5 ms、p95 不超过
   10 ms 的最小 K，才记为新的可部署运行点；若没有 K 通过，保留 Y2 的 K=1000。

第 2 项的 50% 是相对于 Y2 已测池截断差距的预注册效果门槛，不是对所有召回方法的收益上限。
第 4 项只是本轮实验的运行预算，不把 5/10 ms 宣称为通用交互式延迟标准。

## 5. 代码断言与泄漏检查

实现中复用 Y2 的检查，并新增以下断言：

- `n_models == 3_016_439`，三 seed 的 model/dataset/task 映射完全一致；
- eligible query 数严格等于 1,476 / 1,101 / 1,545；
- prior sidecar 只包含对应 seed 的 train+val 边，test query root 不得出现在可见边中；
- exact top-10000 每个查询包含 10,000 个唯一、合法 mappedID；所有较小 K 必须是其严格前缀；
- HNSW 每个 K 返回 K 个唯一、合法 mappedID；
- K=1000 的 exact/HNSW top-K、指标和延迟评测路径与 Y2 一致；
- `G_dense`、`G_full_task`、`G_exact1000_task`、`G_hnsw1000_task` 超出既有浮点容差时拒绝写最终报告；
- 所有指标先逐 seed 计算；不得用均值之比代替逐 seed 比值的均值；
- rescue/harm 必须由保存的逐查询布尔命中向量重新计算，并断言
  `new_hits - baseline_hits == rescue - harm`。

## 7. 执行命令

```powershell
.venv\Scripts\python.exe -m scale1m.eval_y4 --stage exact `
  --device cuda --query-chunk 16 --model-chunk 50000

.venv\Scripts\python.exe -m scale1m.eval_y4 --stage hnsw `
  --hnsw-threads 8

```

若 exact 或 HNSW 阶段运行超过五分钟，只保留上述续跑命令与已完成的原子写入中间件，不持续等待。

## 8. Y4 允许得出的结论

若全部效果门通过，只能说：

> 在冻结 X4-GD 表示和 task prior 的条件下，将 HNSW 候选池扩大到 K，使两阶段系统恢复了至少一半
> 的既有 top-1000 截断差距，并在本机保持预注册的毫秒级延迟预算。

若 exact 扩池有效而 HNSW 未保留增益，只能归因于当前 ANN 参数或实现，不能归因于表示。
若 exact top-10000 仍未恢复一半差距，只能说当前表示下的简单扩池收益有限；不能据此否定其他召回器、
新表示或训练方法。

Y4 不回答 BM25 是否互补、负样本是否充分、哪种损失更好，也不把 task prior 的贡献归入稠密表示。

## 9. 执行结果

初始执行日期为 2026-09-05；最终复跑与 K=1000 系统取舍记录于 2026-09-06。完整机器可读报告见 [`Y4_runs/Y4_REPORT.json`](Y4_runs/Y4_REPORT.json)。

### 9.1 精度曲线

| K | exact seed 0 | exact seed 1 | exact seed 2 | exact 均值 | HNSW 均值 | HNSW 相对 K=1000 |
|---:|---:|---:|---:|---:|---:|---:|
| 1,000 | 0.3286 | 0.3388 | 0.2427 | 0.3034 | 0.3031 | — |
| 2,000 | 0.3327 | 0.3497 | 0.2479 | 0.3101 | 0.3101 | +0.0069 |
| 5,000 | 0.3367 | 0.3533 | 0.2563 | 0.3154 | 0.3154 | +0.0123 |
| 10,000 | 0.3374 | 0.3579 | 0.2570 | 0.3174 | 0.3174 | +0.0143 |
| 全池融合 | 0.3408 | 0.3651 | 0.2589 | 0.3216 | — | — |

从 K=2000 开始，HNSW 与 exact 的 `gold@10` 在三个 seed 上完全相同。K=1000 则精确复现 Y2：
exact 为 0.3034，HNSW 为 0.3031；差异只来自 seed 0 中 HNSW 比 exact 少一个命中。

第一阶段包含 gold 的查询比例随 K 稳定上升：

| K | seed 0 | seed 1 | seed 2 | 三 seed 均值 |
|---:|---:|---:|---:|---:|
| 1,000 | 0.5657 | 0.5940 | 0.3968 | 0.5188 |
| 2,000 | 0.6192 | 0.6649 | 0.4447 | 0.5763 |
| 5,000 | 0.6660 | 0.7302 | 0.5178 | 0.6380 |
| 10,000 | 0.7012 | 0.7648 | 0.5741 | 0.6800 |

### 9.2 差距恢复与逐查询配对

exact K=10000 相对 exact K=1000 的池截断差距恢复率为 72.22% / 72.41% / 88.00%，
三 seed 均值 **77.55%**。因此“至少恢复一半差距”的预注册门通过。

HNSW 相对 K=1000 的逐查询结果为：

| K | seed 0 rescue/harm/net | seed 1 rescue/harm/net | seed 2 rescue/harm/net |
|---:|---:|---:|---:|
| 2,000 | 14 / 7 / **+7** | 14 / 2 / **+12** | 9 / 1 / **+8** |
| 5,000 | 22 / 9 / **+13** | 19 / 3 / **+16** | 23 / 2 / **+21** |
| 10,000 | 23 / 9 / **+14** | 24 / 3 / **+21** | 25 / 3 / **+22** |

所有 K 在所有 seed 上都是净改善，说明提升不是由跨 seed 平均掩盖的。扩大池也会让少量原本命中的 gold
被新增候选挤出 top-10，因此不能把 first-stage gold coverage 的增长直接等同于最终 `gold@10` 增长。

### 9.3 HNSW recall 与延迟

| K | 选中 `ef_search`（seed 0/1/2） | `recall@K`（seed 0/1/2） | p50 均值 | p95 均值 |
|---:|---|---|---:|---:|
| 1,000 | 1000 / 1500 / 1500 | 0.9923 / 0.9941 / 0.9932 | 0.694 ms | 1.223 ms |
| 2,000 | 2000 / 3000 / 3000 | 0.9940 / 0.9961 / 0.9965 | 1.520 ms | 2.757 ms |
| 5,000 | 5000 / 5000 / 5000 | 0.9954 / 0.9923 / 0.9945 | 3.450 ms | 5.979 ms |
| 10,000 | 10000 / 10000 / 10000 | 0.9970 / 0.9953 / 0.9975 | 7.918 ms | 11.755 ms |

所有 recall gate 均通过。K=2000 和 K=5000 通过预注册的 p50 <= 5 ms、p95 <= 10 ms 预算；
K=10000 虽然精度最高，但两项延迟均超出预算。

按照“满足全局扩池有效性、HNSW 增益保留和延迟门后取最小 K”的预注册规则，**实验规则会选中
K=2000**：`gold@10=0.3101`，相对 Y2 K=1000 的 0.3031 增加 0.0069，p50 为 1.520 ms。
若只看 5/10 ms 预算内的最高精度，K=5000 可达到 0.3154、p50 3.450 ms。

**最终系统取舍（2026-09-06）：保留 K=1000。** 上述 K=2000 是预注册选择规则的实验输出，
不是最终部署默认值。考虑到扩大到 K=2000 只增加 0.0069 的平均 `gold@10`，实际系统继续采用
`X4-GD dense -> HNSW top-1000 -> task prior`，对应平均 `gold@10=0.3031`。K=2000/5000/10000
仅作为候选池大小与延迟的敏感度曲线保留。

### 9.5 结论

Y4 成立：在冻结 X4-GD 和 task prior 的情况下，扩大第一阶段候选池可以稳定提高三个 seed 的
`gold@10`；K=10000 恢复了 77.55% 的既有 top-1000 截断差距，证明 Y2 剩余损失中相当一部分确实来自
候选池大小，而不是 HNSW 近似。

预注册规则会选择 K=2000，K=5000 是精度更高的预算内备选；最终部署取舍仍保留 K=1000，
其平均 `gold@10` 为 0.3031。该结果只说明调整现有两阶段系统的 K 有效，不支持关于新表示、
BM25、负采样或损失函数的结论。
