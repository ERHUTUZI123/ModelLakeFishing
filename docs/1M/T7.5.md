# T7.5：这个近似误差会不会在 1M 把性能干掉

上游：[`T7.md`](T7.md) §5.1（G-C2 锚点不通过）。上级：[`100kplan.md`](100kplan.md) §3 T0 / D-14。

**问的不是「历史链条为什么断」，问的是「这东西会不会在 1M 要我们的命」。**
这两个问题的实验设计不一样：前者只要在 12K 上定位一次；
后者必须测**误差随 N 的走向**——因为一个恒定的 −0.03 偏移可以披露掉，
一个随 N 放大的误差会在 1M 把结论变成我们自己的实现噪声。

> **结论（2026-08-14，18 个 run 全部完成）**：
> **两个近似都不会在 1M 干掉精度。** 对比损失采样的误差**随 N 收窄**（0.019→0.012→0.007，全在 1 sd 内）；
> 扇出上限**去掉反而更差、且越大越差**（+0.016→−0.031→−0.058）——它是资产不是负债。
> 任何近似效应 ≤ **0.058**，而规模本身的下降是 **0.148**，**大 2.5–20 倍**。
> 而且精确版在 100K 上贵 **25.6×**、全邻域贵 **21×**，到 1M 根本走不通——
> **近似是必需的，而实验说必需的那个恰好无害。**
> 详见 §5.3；边界与 seed 噪声的警告同样重要，别跳过。

## 1. 先把已经排除掉的排除掉

T0 一共四个开关，不必四个都查——其中两个已经有证据说它们**不引入误差**：

| 开关 | 证据 | 结论 |
|---|---|---|
| `--chunked-infer` | T7 的 G-A2 实测 `max|Δ| = **0.00e+00**`（12K/30K，逐位相同，不是"小于容差"） | **零误差**，排除 |
| `--sparse-M` | T0 的 `test_sparse_M_equivalence`：稀疏版 `.to_dense()` 与稠密版**逐元素相等** | **构造上等价**，排除 |
| `--contrast-n-neg 256` | 🔴 D-14 明标「**改动冠军配置**」，要求 A/B 对拍，而那张表**从未产出** | **候选 1** |
| `--fanout` | 改变每个节点看得见的邻居；hub 越大丢弃比例越高 | **候选 2** |

⇒ 只需要两条臂。**这不是省事，是把实验打在真正带风险的两个量上。**

## 2. 两个候选各自的「会不会随 N 变坏」的机理

**`--contrast-n-neg`**：对比损失的分母从「子图内全部 N²」换成「每锚点采 256 个负例」。
分母的总体是**采样子图**，而子图大小被 `--fanout` 压着，所以它**未必**随 N 增长——
这一条是真的说不准，必须实测。（注意：配置里的 `global_n_neg=256` 是 L1 全湖项、**P3 那时就是 256**，
不是 T0 引入的，不在本次范围内。）

**`--fanout`**：把每跳邻居截到 (10,10)（血缘 (20,20)）。
N 从 12K 涨到 100K 时，监督边冻结不变、但 hub 的度数在涨
（[`T6more.md`](T6more.md) 记过 100K 上 `mradermacher` 独占 HALO 的 20.1%），
**同一个上限丢弃的比例就更高**。这一条有明确的「随 N 变坏」的理由。

## 3. 设计

固定其余一切（同图、同 `split_seed`、同 25 epoch、同 L1L3b 配置），每档三个 seed：

| 臂 | 开关 | 含义 |
|---|---|---|
| `approx` | `--fanout --sparse-M --contrast-n-neg 256 --chunked-infer` | 现在出货的这一套（T6/T7 已有） |
| `exact` | 去掉 `--contrast-n-neg` | 对比损失回到全 N² |
| `nofanout` | 去掉 `--fanout` | 邻域回到全闭包 |

档位 12K / 30K / 100K，共 18 个训练 run（含补齐 30K 的 `approx` seed 1/2）。
`nofanout` 在 100K 上**只跑一个 seed 作可行性探针**——那正是 T0 第 1 项当初被造出来要避免的情形。

> 🔑 **「跑不完」本身就是结果。** 如果 100K 上去掉扇出根本跑不动，
> 那说明**这个近似在规模上不是可选项**，于是问题从「要不要用近似」变成
> 「必须用近似，所以必须把它的误差刻画清楚并披露」。这两种结局都要照实写。

**跑在 CPU 上**：可用 GPU 池全满（T7 已经吃过这个亏），而导出与训练都不必须 GPU；
按 D-45 先用一个探针实测（12K `exact` 25 epoch ≈ **12 分钟**）再定各档 `--time`。

## 4. 🔒 判定规则（**在看到任何结果之前写下**）

设 `Δ(N) = gold@10(exact 或 nofanout) − gold@10(approx)`，每档取三 seed 均值。

| Δ(N) 的形状 | 判定 | 行动 |
|---|---|---|
| **Δ 在 12K→100K 上基本不变或收窄** | 近似是**规模无关的常数偏移** | R3/R4 照用；报告里把这个偏移量作为已知代价明写 |
| **Δ 随 N 单调放大** | 🔴 **这就是会在 1M 干掉我们的东西** | R3/R4 之前必须换实现：对比损失走 D-14 的 B 方案（分块 logsumexp，**数学等价**、只省显存不省时间）；扇出上限按 N 重新标定 |
| **Δ 在噪声内（\|Δ\| < 同档三 seed 的 sd）** | 该近似**无罪** | 把嫌疑转给另一条臂；两条臂都无罪 ⇒ 差异来自环境/采样后端，与 1M 风险无关 |

**同时记录「精确的代价」**（`wallclock(exact) / wallclock(approx)`）：
如果精确版在 100K 上只贵 2–3 倍，那么"直接用精确版"就是最省事的修法，根本不用争论误差大小。
**这一列和 Δ 同等重要**，它决定修法是"换实现"还是"接受并披露"。

**外推到 1M 的纪律**：三个点拟合曲线，`100kplan.md` §17 已经写死「**曲线拟合只有 3 点，不下结论，等 R3/R4**」。
所以本篇**只报 Δ 的方向与量级**，不给 1M 的点估计。方向本身就足以决定要不要改实现。

### 5.2 核心表：Δ 随 N 怎么走

**候选 1 —— 对比损失采样（`--contrast-n-neg 256`）**

| rung | N | exact | approx | **Δ** | \|Δ\|/sd | 精确的代价 |
|---|---:|---:|---:|---:|---:|---:|
| 12k | 12,000 | 0.3828 | 0.3633 | **+0.0194** | 0.95 | 6.3× |
| 30k | 30,183 | 0.2416 | 0.2295 | **+0.0122** | 0.48 | 3.2× |
| 100k | 100,000 | 0.2214 | 0.2145 | **+0.0069** | 0.15 | **25.6×** |

⇒ **Δ 是正的（精确略好），但随 N 单调收窄**：0.019 → 0.012 → 0.007，
且三档都在 **1 个 seed 标准差以内**。**没有放大迹象，方向相反。**

**候选 2 —— 扇出上限（`--fanout`）**

| rung | N | nofanout | approx | **Δ** | \|Δ\|/sd | 去掉的代价 |
|---|---:|---:|---:|---:|---:|---:|
| 12k | 12,000 | 0.3789 | 0.3633 | +0.0155 | 0.76 | 4.3× |
| 30k | 30,183 | 0.1984 | 0.2295 | **−0.0311** | 1.23 | 1.3× |
| 100k | 100,000 | 0.1567 | 0.2145 | **−0.0579** | 1.24 | 21.0× |

⇒ **符号翻转，而且反过来**：12K 上去掉扇出略好，30K/100K 上去掉扇出**明显更差**，
且**差得越来越多**（+0.016 → −0.031 → −0.058）。
**扇出上限不是负债，它是随 N 增值的资产**——这与 GraphSAGE 邻居采样本身的正则化作用一致，
也与 hub 越大、全邻域聚合过平滑越严重的机理一致。

### 5.3 判定（按 §4 预先写死的规则）

| 候选 | 规则命中 | 判定 |
|---|---|---|
| `--contrast-n-neg 256` | 「Δ 在噪声内」+「Δ 随 N 收窄」 | ✅ **无罪，且风险随 N 下降** |
| `--fanout` | Δ 反向且随 N 放大 —— **去掉它才有害** | ✅ **无罪，且是随 N 增值的收益** |

**⇒ 对你的问题的直接回答：这两个近似不会在 1M 把检索精度干掉。**

三条支撑：

1. **量级对比才是关键**。任何近似效应的绝对值 ≤ **0.058**，而**规模本身**带来的下降是
   12K 0.363 → 100K 0.215 = **0.148**——**大 2.5–20 倍**。近似不是主因。
2. **两个近似的方向都不是"随 N 变坏"**：一个收窄，一个反向增值。
   §4 里那条会触发「R3/R4 前必须换实现」的形状，**一个都没出现**。
3. **而且精确版在规模上根本不可行**：`exact` 在 100K 上贵 **25.6×**（2,798 s vs 109 s），
   `nofanout` 贵 **21×**。到 1M 这两条路都走不通。
   **所以近似不只是安全的，它是必需的——而实验说必需的那个恰好也是无害的。**

> 🔴 **诚实的边界：这是"测不出"，不是"证明为零"。**
> 每档 3 seed、sd 在 0.020–0.074 之间，这个样本量只能分辨 **≳0.05** 的效应。
> 所以正确的表述是：**任何随 N 放大的近似误差，其上界低于 0.05，也低于 seed 噪声本身。**
> 100K 的 `nofanout` 只有 1 个 seed（设计如此，可行性探针），那一格不参与统计判断。
> `100kplan.md` §17 的纪律照旧：三个点不外推 1M 的点估计。

> 🟠 **顺带一个必须写下来的观察：seed 噪声压倒一切。**
> `exact` 在 12K 上三个 seed 是 0.4681 / 0.3407 / 0.3395（sd 0.074）——**seed 0 那一格比 P3 的 0.4159 还高**。
> 这说明 §5.1 里任何**单 seed** 的比较都没有意义，也再次印证 v4 W3 的教训
>（3-seed 结论在 8 seeds 下不成立）。**T8 报任何 A 轴数字都必须带 seed 区间。**

### 5.4 那 G-C2 的 −0.029 到底是什么

两条臂都无罪 ⇒ 按 §4 第三行，差异归到**环境/采样后端**
（P3 无 `pyg-lib` 走纯 Python 全邻域，现在走 PyG 的 C++ 采样器）**与 1M 风险无关**。

但要注意 §5.1 的数字让这件事本身也松动了：12K `exact` 的 seed 0 是 **0.4681**，
比 P3 的 0.4159 还高 0.05。**「0.4159」看起来更像是一个高方差分布里的一次抽样，
而不是一条可复现的基线。** 这与 [`T7.md`](T7.md) §1.7 查到的事实吻合——它本来就是**单次**运行的结果。

⇒ **建议把 G-C2 从「锚点必须复现到某个点值」改写成「12K 的 3-seed 区间必须覆盖历史值」**，
并登记为一条决策。按这个口径：12K approx 区间 [0.349, 0.387]，历史值 0.4159 仍在区间外，
但 `exact` 区间 [0.340, 0.468] **覆盖**它。这条改写需要你拍板，不在本篇擅自执行。
