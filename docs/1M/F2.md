## 1. 结论

三百万条记录的节点属性与监督边都已产出，与 F1 的九项锚点逐项相符。

监督最终是 **74,346 条边、7,944 个 (数据集, 任务) 节点**，其中 **2,041 个节点合格作为评测查询**。
gold 构造规则已冻结为 `rf_gold_rules.json`（版本 `rf-gold-1.1`，
sha256 `ee3eb185d5e7243cd8668a41adaab62816b1f008f3a215615e4ba90652efaee6`）。

三件在本阶段定案、且都必须在看到任何精度数字之前定下来的事：

**指标方向的覆盖率是 71.69%。** 按记录数，higher 70.96%、lower 0.73%、reward 2.69%、unknown 25.62%。
unknown 那一片几乎全是 `nauc_*` 这类 MTEB 排序难度诊断量，它们本来就不是质量分数，
被挡在 gold 之外是正确行为而不是损失。

**监督高度集中，边数上限确实在做事。** 设限前 143,478 条边里有 **95,332 条（66.4%）挂在 131 个节点上**；
设限后这 131 个节点只保留 26,200 条，数据集维度的有效数（1/HHI）从 177.6 升到 520.8，
top-10 数据集份额从 14.95% 降到 5.32%。

**强化学习组是被自己的数值格式淘汰的，不是被我们的规则挡掉的。** `mean_reward` 的数值有 97% 是
`"11.05 +/- 5.90"` 这种字符串（HF Deep RL 课程排行榜的格式），解析不出数值，
因此 61,294 条记录在第一步就被丢弃。D-59 的 RL 排除与边数上限对它几乎没有起作用的机会——
RL 在最终监督里只占 0.24%。这一点必须写进报告，否则读者会以为是我们的规则起了作用。

## 3. 节点属性

```bash
python -m scale1m.canonicalize_rf \
  --candidates $MLF_DATA_DIR/data1m/candidates_full \
  --out        $MLF_DATA_DIR/data1m/rf
```

产物是 61 个 `canon/part-*.parquet`（与输入分片一一对应，流式写出，峰值内存被单片 5 万行限制住），
每行含 `size_b`、`family`、`family_source`、`lineage_base`、`lineage_relation`、`lineage_source`、`layer`。

`size_b` 仍然只取 `safetensors.total`，不加名字正则兜底（D-26）。

`family` 的解析规则比 100K 档短了一半。那时是四级解析，前两级的作用是「落进 CORE 的 embedding 表已经用过的家族」，
好让 HALO 的 llama 和 CORE 的 llama 共用一行。CORE 退出后没有可对齐的命名空间，
规则退化为：有 `config.model_type` 就用它，否则用小写化的名字规则输出。
实测 `config.model_type` 命中 1,061,240 条（35.3%），其余 1,942,519 条走名字规则。
`family_source` 逐行记录哪一条规则生效。

`lineage_base` 仍是 `baseModels` 优先、`cardData.base_model` 兜底，并保留 `relation`。
2,109,670 条记录没有任何血缘声明。

## 4. 监督构造

规则顺序与 1Mplan §3.2–§3.4 一致，每一步的量都记在 `F2_REPORT.json` 里。

| 步骤 | 结果 |
|---|---|
| 从 `model-index` 解析出的原始指标行 | 2,158,375 |
| 数值无法解析或非有限，丢弃 | 61,294（2.84%） |
| 进入归一化的行 | 2,097,081 |
| 按 (模型, 数据集, 任务, 指标) 取中位数后 | 1,435,162（合并掉 661,919 条重复，31.6%） |
| 组内取值恒定、归一化置 0.5 的行 | 38,358 |
| (数据集, 任务) 节点 | 7,944 |
| 主指标方向已知的节点 | 6,820（85.8%） |
| 边（每节点只用主指标） | 143,478 |
| 每节点 200 条上限后 | **74,346** |
| 被上限截断的节点 | 131 |

### 4.1 方向先于归一化

指标名先规范化（小写、`@` → `_at_`、分隔符统一），再按 `scale1m/metric_semantics.py` 判方向。
判定是按**模式**而不是逐条枚举的：快照里有 2,776 个不同的原始指标名，
头部是同一族在不同截断与不同相似度函数下的重复（`ndcg_at_1` 到 `ndcg_at_1000`、`cosine_ndcg@10`），
逐条列举必然漏。查表时剥掉截断后缀与相似度前缀取基名，基名不在表里就落 `unknown`，不猜。

按记录数的四类分布：

| 类别 | 记录数 | 占比 | 不同指标名 |
|---|---|---|---|
| higher（直接用） | 1,539,828 | 70.96% | 374 |
| lower（归一化后取 `1 − v`） | 15,835 | 0.73% | 31 |
| reward（保留边，不进 gold） | 58,456 | 2.69% | 5 |
| unknown（保留边，不进 gold） | 555,929 | 25.62% | 2,084 |

unknown 的头部是 `nauc_map_at_1000_diff1`、`nauc_mrr_at_100_max` 这一族，
每个名字各 4,639 条。它们是 MTEB 的排序难度诊断量，不是质量分数，两个方向都说不通，
落进 unknown 正是应有的结果。

### 4.2 分组键与去重

分组键是 (dataset, task, full_metric_name)，指标名不做语义合并：
`ndcg_at_1` 与 `ndcg_at_10` 是两组，`accuracy` 在 `Classification` 与 `text-generation` 下也是两组。
单测 `test_normalisation_is_per_full_metric_name_not_pooled` 钉住了这条。

同一 (模型, 数据集, 任务, 指标) 的多条记录取**中位数**。这一步合并掉 661,919 行，占原始行的 31.6%——
重复提交在这份语料里是常态而不是例外，取最大值会系统性地把边权抬高。

### 4.3 主指标与 gold 资格

每个节点选一个主指标，边权只用它：方向已知的指标优先，其次 reward，最后 unknown。
按主指标的方向类别分，7,944 个节点是 higher 5,374 / lower 1,446 / unknown 1,073 / reward 51。

方向未验证的节点**保留边、但不进 gold**（D-61）。这是这次实现里改过一次的地方：
第一版直接把 reward 与 unknown 整类丢掉，导致这些节点连边都没有，与冻结规则不符，已修正并重跑。

gold 资格要同时满足四条：主指标方向已知、非强化学习任务、数据集名不是占位名、模型数 ≥3。

| 从 7,944 个有边节点里排除 | 节点数 |
|---|---|
| 主指标方向未验证 | 1,124 |
| 强化学习任务 | 56 |
| 占位数据集名 | 152 |
| 模型数少于 3 | 5,467 |
| **合格查询节点** | **2,041** |

### 4.4 占位数据集名：本阶段新增的一条冻结规则

按边数排前几位的「数据集」是 `unknown`（1,085 条边）、`custom`（579）、`none`（427）。
其中 `unknown / triplet` 一个节点就挂着 896 个模型。这不是一个数据集：
每个作者写 `unknown` 时指的是各自不同的语料，把它们并成一个节点，
等于让 gold 去比较 896 个在 896 个互不相关的数据上评出来的模型。

因此在 `rf-gold-1.1` 里加了一份占位名黑名单（`unknown`/`custom`/`none`/`private`/`internal` 等 19 个），
命中的节点**保留边、排除出查询集**，与方向未验证的节点同样处理。
影响：合格查询节点从 2,093 降到 2,041，涉及边 1,781 条。

这条规则是在看到任何精度数字之前定的，符合约束 4；此后若要改动，需要新起版本号并重跑。

### 4.5 边数上限

每个 (数据集, 任务) 节点最多保留 200 条监督边，超出部分按边权分层抽样（`default_rng(0)`，可复现）。

| 量 | 设限前 | 设限后 |
|---|---|---|
| 边数 | 143,478 | 74,346 |
| 被截断的节点数 | — | 131 |
| 这 131 个节点持有的边 | 95,332（**66.4%**） | 26,200 |
| 数据集有效数（1/HHI） | 177.6 | 520.8 |
| 最大数据集份额 | 2.85% | 1.46% |
| top-10 数据集份额 | 14.95% | 5.32% |

1.6% 的节点持有三分之二的监督，这正是 §3.3 设上限的理由，现在有了数字。
上限值 200 是拍的，本次没有据此调整；若要改，属于 `rf_gold_rules.json` 的版本变更。

分层抽样保住了取值分布的形状，单测断言截断后两端仍在（最小 < 0.1、最大 > 0.9）。

### 4.6 监督分布（§3.3.1 要求的三个维度）

按任务，设限后边数前几位是 Retrieval 11,922 / text-generation 10,061 /
automatic-speech-recognition 6,631 / Classification 5,059 / Clustering 4,267 / text-classification 4,039。
查询节点按任务前几位是 text-generation 304 / automatic-speech-recognition 287 /
text-classification 154 / Retrieval 147 / token-classification 126。

按主指标，边数前几位是 accuracy 16,437 / ndcg_at_10 11,082 / wer 6,463 / v_measure 4,123 /
euclidean_pearson 3,412 / f1 3,125 / map 2,729 / bleu 2,434。

按数据集，设限后前五位是 `unknown` 1,085 / `custom` 579 / `none` 427 / `samsum` 336 / `audiofolder` 326。
前三个是占位名：它们有边但不产生查询（§4.4），读这张表时不能把它们当成真实的大数据集。

强化学习在最终边里占 0.24%（设限前 0.12%），原因见 §5。

### 4.7 查询深度

`≥3` 是最低可用门槛，不是可靠性保证，因此四档都统计：

| 深度 | 合格查询节点 |
|---|---|
| ≥3 | **2,041** |
| ≥5 | 1,304 |
| ≥10 | 772 |
| ≥20 | 513 |

主表深度定为 ≥3 并写进冻结规则，其余三档在 F8 作为稳健性附表各报一遍；
若不同深度给出的结论方向相反，以更深的那一档为准并写明。合格节点的模型数中位数是 6，
均值 63，最大 4,094——分布很偏，这也是要同时看 ≥10 / ≥20 的原因。

## 5. 强化学习组的实际去向

计划（D-59）设想的是 RL 保留在图里、排除出查询集，并靠 200 条上限压住它的边数。
实测的路径不是这样：`mean_reward` 的数值有 97% 是 `"11.05 +/- 5.90"` 这种「均值 +/- 标准差」字符串，
`to_float` 解析不出来，因此在第一步就作为「非有限或不可解析」被丢弃，共 61,294 条。

结果是 RL 在最终监督里只剩 0.24%，而这几乎全部来自那 3% 数值是纯数字的记录。
`lunarlander-v2` 这类节点因此没有出现在 top 数据集里，也不需要靠上限来压。

**定案：不为这个格式加解析器**，理由有两条。这一群本来就要排除出查询集，解析出来只会给训练图增加
约 5 万条来自同一门公开课的边；而且不解析让丢弃量留在账上（61,294 条，2.84%），
比解析后再排除更容易审计。这条写进了 `rf_gold_rules.json` 的 `value_parsing` 段。

需要一起说明的是：这意味着「RL 不主导监督」这个结果**不是我们的规则挣来的**，
报告里不能把它写成排除策略的成效。

## 7. 与计划的偏离

| # | 计划原文 | 实际 | 理由 |
|---|---|---|---|
| 1 | `hf_canonicalize --native-supervision` | 新模块 `scale1m/canonicalize_rf.py` | 原模块把全部记录一次性读进内存，且 family 解析依赖 CORE 的命名空间。三百万条要流式处理，CORE 又已退出，改动量大于新写一个；100K 档的复现路径因此保持不动 |
| 2 | family 四级解析 | 二级：`config.model_type`，否则名字规则 | 前两级的目标是落进 CORE 用过的家族，CORE 退出后没有这个目标 |
| 3 | 计划未规定占位数据集名 | 新增黑名单，节点保留边但排除出查询集，规则版本升到 `rf-gold-1.1` | `unknown / triplet` 一个节点 896 个模型，gold 在其上无意义。按约束 4，这条在看到精度数字之前定案 |
| 4 | 计划假设 RL 需要靠上限压制 | RL 因数值格式自行淘汰，上限对它没起作用 | 见 §5。不加解析器，并在报告里写明这不是规则的成效 |
| 5 | — | 第一版实现把 reward 与 unknown 整类丢弃 | 与 D-61「保留边、不进 gold」不符，已修正并重跑，本文的数字来自修正后的版本 |

## 9. 第二阶段：六来源监督合并（2026-08-19）

§1–§8 记录的是纯快照口径。按 D-63，监督扩展为六个来源合并，候选池仍只由快照定义。
本节记录合并的执行与结果；上面那些数字没有作废，它们现在是 `hf_model_index` 这一个来源的数字。

```bash
python -m scale1m.canonicalize_rf   --candidates .../candidates_full --out .../rf   # 重跑，补出未设限的边
```

phase 1 重跑了一次，只为多产出 `supervision_uncapped.parquet`：
每节点 200 条的上限必须在六源合并**之后**只施加一次，否则快照来源会被截断两次。

### 9.2 合并流程的每一步

| 步骤 | 结果 |
|---|---|
| 六源边合计 | 531,958 |
| 各源组内重复取中位数 | 合并掉 5,102 条 |
| 按 (节点, 来源) 重做 min-max | 22,525 行落在取值恒定的组，置 0.5 |

18,729 个数据集节点里只有 299 个（1.6%）同时来自多个来源。
每个节点的 `gold_source` 记为该节点上优先级最高的来源，gold 由它决定。

| 量 | 纯快照口径 | 六源合并 | 倍数 |
|---|---|---|---|
| 监督边 | 74,346 | **247,803** | 3.33× |
| 数据集节点 | 7,944 | **18,729** | 2.36× |
| 合格查询节点 | 2,041 | **7,859** | 3.85× |
| 查询节点（≥5 / ≥10 / ≥20） | 1,304 / 772 / 513 | **5,526 / 3,450 / 1,909** | 4.2× / 4.5× / 3.7× |

监督规模也超过了 100K 档单用 ModelLens 时的 312,986 条的可比部分：
那时是一个来源的全部边，这里是六个来源在每节点 200 条上限后的合计。

湖外模型是 12,680 个而不是 §3.7 预估的 16,713 个：差额是那些模型的边在 200 条上限里被抽掉了，
既然没有边留下，它们也就没有理由进湖。这个数字要按最终边集算，不能按合并前算。

### 9.4 gold 资格与排除

| 从 18,729 个节点里排除 | 节点数 |
|---|---|
| 主方向未验证 | 1,119 |
| 强化学习任务 | 58 |
| 占位数据集名 | 170 |
| 模型数少于 3 | 10,429 |
| **合格查询节点** | **7,859** |

占位名黑名单在 `rf-gold-2.0` 里增加了 ModelLens 自己的占位符 `##`——
