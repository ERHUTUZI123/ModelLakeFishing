# Z1：K=1000 第二阶段固定融合校准

> 状态：已执行（2026-09-06）。依据 [`Z0.md`](Z0.md) 方向一；实验未通过预注册的稳定性判据，实际系统保持 `K=1000, raw, beta=1, shrink=5`。

## 1. 问题

当前实际系统固定为：

```text
X4-GD / HNSW top-1000 -> (cos+1)/2 + task_prior -> top-10
```

Z1 只回答：当前 dense 与 task prior 的等权相加是否存在分数尺度失配；简单、固定的校准能否在不训练新
ranker 的情况下稳定提高 `gold@10`。

## 2. 无泄漏开发集

- 对每个 split seed 重新构造 validation message graph，只包含 train roots 的 `trained_on` 边。
- 从相同 X4-GD checkpoint 在该图上重新导出 validation embedding；不得使用包含 validation 边的现有
  `z_*_eval`。
- validation task prior 只读取 train edges；test task prior 继续只读取 train+val edges。
- validation 使用 exact dense top-1000，避免为一次权重选择新建三份 2.2 GiB HNSW 索引。Y2 已证明
  K=1000 HNSW 对 exact 的误差可忽略；最终 test 必须使用实际 HNSW top-1000。
- Y4 test 产物不得参与选参；冻结配置后 test 只评测一次。

## 3. 固定搜索空间

只搜索相对权重，令 dense 系数固定为 1：

```text
score = calibrated_dense + beta * calibrated_prior
```

| 项 | 固定候选 |
|---|---|
| calibration | `raw` / query 内 `zscore` / query 内 tie-aware `percentile` |
| `beta` | 0 / 0.125 / 0.25 / 0.5 / 1 / 2 / 4 / 8 |
| prior shrink `k` | 1 / 5 / 20 |

`beta=0` 只保留一份 dense-only 对照。当前系统是 `raw, beta=1, shrink=5`。三个 seed 共用同一个最终配置：
先最大化 validation 三 seed 平均 `gold@10`，并依次用最差 seed、与当前配置的复杂度距离和字典序打破并列。
不追加搜索点。

## 4. 必报结果

- 同一 top-1000 池内的 dense-only、prior-only、当前等权融合与最佳校准；
- validation 与 test 的逐 seed `gold@10`、`gold@1`、`top3@10`；
- 最佳校准相对当前融合的逐查询 rescue/harm；
- dense/prior 的 query 内标准差和 top-1/top-10 margin；
- top-10 模型 `size_b` 中位数与缺失率；
- 重排和端到端 p50/p95。

## 5. 判据

只有以下条件全部满足，才能说固定校准有效：

1. 最佳配置在 validation 三 seed 均值上严格超过当前等权融合；
2. 冻结后 test 三个 seed 均不下降，且每个 seed `rescue > harm`；
3. test 平均 `gold@10` 严格超过 Y2 实际系统的 0.3031；
4. 端到端 p50 <= 5 ms、p95 <= 10 ms；
5. top-10 非缺失 `size_b` 中位数不超过当前融合的 2 倍，且大小缺失率不得增加超过 5 个百分点。

若不通过，保留 `raw, beta=1, shrink=5`，并将“简单尺度校准不是缺失增量”作为 Z1 的负结果。

## 7. 执行结果

### 7.1 口径与验证集选择

三组 validation-safe 表示均由对应 X4-GD checkpoint 在仅含 train-root `trained_on` 边的图上重新导出；
validation prior 仅使用 train edges。三个 seed 的 eligible validation queries 分别为 347、548、732。
图与 checkpoint 绑定、root 隔离、prior 边界和既有 test sidecar 复现断言均通过。

验证集按预注册规则选中：

```text
calibration = raw, beta = 8, shrink_k = 20
```

它没有选中 `zscore` 或 `percentile`；增量来自提高 task-prior 的全局权重并加强 shrink。该配置位于预注册
`beta` 网格的上边界，未继续追加搜索点。

| 配置 | seed 0 | seed 1 | seed 2 | 三 seed 均值 |
|---|---:|---:|---:|---:|
| 当前：raw, beta=1, k=5 | 0.1527 | 0.4599 | 0.1735 | 0.2620 |
| 验证选中：raw, beta=8, k=20 | 0.1643 | 0.5949 | 0.2008 | 0.3200 |

验证集逐查询 rescue/harm 为 `8/4`、`80/6`、`29/9`，因此允许冻结该配置进入一次 test 评测。

### 7.2 冻结后的 3M HNSW 测试

以下四种方法共享每个查询的实际 HNSW top-1000 候选池；表中为 eligible-query `gold@10`。

| 第二阶段分数 | seed 0 | seed 1 | seed 2 | 三 seed 均值 |
|---|---:|---:|---:|---:|
| dense-only | 0.1355 | 0.1417 | 0.1508 | 0.1427 |
| task-prior-only | 0.3279 | 0.3134 | 0.2058 | 0.2824 |
| 当前融合：raw, beta=1, k=5 | 0.3279 | 0.3388 | 0.2427 | 0.3031 |
| 验证选中：raw, beta=8, k=20 | 0.3496 | 0.3333 | 0.2595 | 0.3142 |

验证选中配置相对当前融合的逐查询 rescue/harm：

| seed | queries | rescue | harm | net | `gold@10` 变化 |
|---|---:|---:|---:|---:|---:|
| 0 | 1,476 | 51 | 19 | +32 | +0.0217 |
| 1 | 1,101 | 24 | 30 | -6 | -0.0054 |
| 2 | 1,545 | 36 | 10 | +26 | +0.0168 |

补充指标的三 seed 均值如下：

| 配置 | `gold@1` | `top3@10` |
|---|---:|---:|
| dense-only | 0.0233 | 0.2528 |
| task-prior-only | 0.1275 | 0.3330 |
| 当前融合 | 0.1274 | 0.3737 |
| 验证选中 | 0.1356 | 0.3687 |

### 7.3 延迟、大小检查与判定

验证选中配置的端到端 p50/p95（ms）分别为 `0.472/0.813`、`1.033/1.967`、
`0.685/1.221`；其中第二阶段重排 p50 仅为 `0.069`、`0.073`、`0.078` ms。
三个 seed 的 top-10 非缺失模型大小中位数均未超过当前融合的两倍，大小缺失率也未增加 5 个百分点。

| 预注册 gate | 结果 |
|---|---|
| validation 均值提高 | 通过 |
| test 三 seed 均不下降 | **失败**（seed 1：0.3388 -> 0.3333） |
| test 每个 seed 均 rescue > harm | **失败**（seed 1：24 < 30） |
| test 均值超过 0.3031 | 通过（0.3142） |
| 端到端延迟预算 | 通过 |
| 模型大小偏置检查 | 通过 |
| 精确复现 Y2 当前系统 | 通过 |

因此，Z1 **不能证明固定融合校准带来稳定增量**。更强 task prior 权重把测试均值提高了 0.0110，
但该收益没有跨 seed 稳定成立；`zscore` 和 `percentile` 也未被验证集选中。论文和实际系统继续使用
`HNSW K=1000 + raw beta=1, shrink=5 task prior`，Z1 只保留为论文外的负结果。
