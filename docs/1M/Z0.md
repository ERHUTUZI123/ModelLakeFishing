# Z0：gold@10 还有多少提升空间

> 状态：2026-09-08 重写。旧版 Z0 是"融合与重排方向备忘"，其方向一、方向二已分别由
> [`Z1.md`](Z1.md)、[`Z2.md`](Z2.md) 执行并否定，方向三/四的启动条件因此没有成立。本文取代旧版：
> 先逐项核验 Z1/Z2，再把"还有没有空间"从直觉问题变成一个可以算出来的上界问题。
>
> 本文只做只读核算，不修改任何实现、评测或实际系统。实际系统仍为
> `HNSW K=1000 + raw beta=1, shrink=5 task prior`，三 seed 平均 `gold@10 = 0.3031`。

---

## 1. 结论

有空间，但几乎全部不在 Z 系列一直在找的地方。

把候选池固定为 K=1000 之后，第二阶段能做的事情存在一个**可以精确算出的天花板**：任何在 dense 分数和
task prior 上同时严格单调递增的打分函数（包含 Z0 旧版方向一、Z1 的全部常数配置、Z2 的自适应 gate，
以及任何未来的加权、校准、门控变体），三 seed 平均 `gold@10` 最高只能到 **0.3827**。当前系统 0.3031，
Z2 已达 0.3148。也就是说：

- **第二阶段融合剩余空间最多 +0.068**（0.3827 − 0.3148），而且其中可学习的部分更小：一个能对每个查询
  挑出 Z1 预注册网格里最优 `(beta, shrink)` 的**作弊 gate** 只能到 **0.3555**，Z2 用真实特征只拿到 0.3148。
- **同一个池上，完美重排器能到 0.5190**。天花板与融合天花板之间的 **0.136** 差距，靠任何 dense×prior
  的单调组合都取不到，必须引入第三路信号。
- **把 K 放大到 10,000，池天花板升到 0.6800，但现融合只吃到其中 8.9%**（`gold@10` 0.3031 → 0.3174）。
  加深召回本身不解决问题。

因此答案是：**继续调融合权重／门控／校准的空间已经基本用尽（上限 +0.068，可实现部分远小于此，且 Z1/Z2
已证明跨 seed 不稳定）；真正的空间在第一阶段表示和"第三路信号"上，量级是前者的 2 倍以上。**

### 2.3 核验中发现、但两篇文档没有写出的三点

1. **Z1 选中配置落在预注册网格边界。** `beta = 8` 是网格上界，验证集最优点不是内点，说明"最好的常数"
   可能根本不在搜索范围内。Z1 正确地没有追加搜索点，但这意味着 Z1 的负结果是"该网格内没有稳定增量"，
   而不是"常数校准的上界只有 0.3142"。第 3 节直接给出该上界，补上这个缺口。
2. **开发集与测试集不可交换。** 生产配置在 validation 上是 0.1527 / 0.4599 / 0.1735（均值 0.2620），
   在 test 上是 0.3279 / 0.3388 / 0.2427（均值 0.3031）。逐 seed 难度顺序甚至翻转：seed 1 在 validation
   上远比 test 容易，seed 0 相反。Z1 的 `beta=8` 之所以在 seed 0/2 上有效、在 seed 1 上有害，与这个
   分布错配直接相关。validation query 数只有 347 / 548 / 732，也远小于 test。
3. **Z2 的分层表暴露了真正的难度轴。** 按 task-model-support 三分位分层后，`gold@10` 在三个 seed 上
   **单调地随支持度上升而下降**：

   | seed | low 支持度 | mid | high |
   |---|---:|---:|---:|
   | 0 | 0.5766 (n=659) | 0.1379 (116) | 0.1255 (701) |
   | 1 | 0.8170 (235) | 0.4100 (200) | 0.1486 (666) |
   | 2 | 0.3035 (1038) | 0.1954 (174) | 0.0781 (333) |

   即：历史证据越多的热门任务，系统越差。Z2 的 gate 特征全部按"支持度越高越该信 prior"定向并加了单调
   约束，方向本身没错（prior 确实更可信），但它优化的不是失败发生的地方——失败发生在**竞争者太多**的
   任务上，而不是 prior 不可信的任务上。这解释了为什么三个支持度类特征的系数被压到 0。

## 3. 三条天花板

以下全部在同一批 eligible test queries（1,476 / 1,101 / 1,545）与同一批 K=1000 HNSW 池上计算，
三 seed 非加权平均。

### 3.1 融合天花板（本文新算）

设 gold 为 `g`，池内候选 `c`。若存在 `c ≠ g` 满足 `dense_c ≥ dense_g` 且 `prior_c ≥ prior_g`，且至少一项
严格大于，则对**任何在两个参数上都严格单调递增的打分函数** `f`，必有 `f(c) > f(g)`。于是

$$
\text{gold@10 可达} \Longrightarrow \bigl|\{c \ne g : c \succeq g\}\bigr| \le 9 .
$$

这个条件与 `f` 的具体形式无关，因此它同时是 Z0 旧版方向一、Z1 全部 24 个网格点、Z2 的 query-level gate、
以及任何 per-query 权重、per-candidate 校准、单调变换的**共同上界**。

对每个 shrink 分别计算，再与两个退化端点（只用 dense、只用 prior）取并集，得到覆盖整个两信号打分族的
上界：

| 上界族 | seed 0 | seed 1 | seed 2 | 三 seed 均值 |
|---|---:|---:|---:|---:|
| 严格单调 (dense, prior k=1) | 0.3889 | 0.3997 | 0.2744 | 0.3543 |
| 严格单调 (dense, prior k=5) | 0.4085 | 0.4151 | 0.2913 | 0.3716 |
| 严格单调 (dense, prior k=20) | 0.4072 | 0.4133 | 0.2913 | 0.3706 |
| 只用 prior k=20 | 0.3421 | 0.3115 | 0.2175 | 0.2904 |
| 只用 dense | 0.1355 | 0.1417 | 0.1508 | 0.1427 |
| **并集：两信号打分族的上界** | **0.4187** | **0.4296** | **0.2997** | **0.3827** |

### 3.2 池天花板

一个能任意重排 K=1000 池的完美重排器，其 `gold@10` 恰等于 gold 落入池内的比例：

| | seed 0 | seed 1 | seed 2 | 均值 |
|---|---:|---:|---:|---:|
| 池天花板 | 0.5650 | 0.5940 | 0.3981 | **0.5190** |

### 3.3 完整阶梯

| 打分方式 | 三 seed 均值 `gold@10` | 占池天花板 |
|---|---:|---:|
| 只用 dense | 0.1427 | 27.5% |
| 只用 task prior（池内） | 0.2824 | 54.4% |
| **生产配置 beta=1, k=5** | **0.3031** | 58.4% |
| Z1 最优常数 beta=8, k=20 | 0.3142 | 60.5% |
| Z2 置信度自适应 gate | 0.3148 | 60.7% |

| **两信号打分族上界（§3.1）** | **0.3827** | **73.7%** |
| **池天花板：完美重排器 @K=1000** | **0.5190** | 100% |
| 池天花板 @K=10,000 | 0.6800 | — |

## 4. 查询级四分解

把每个 eligible test query 归入互斥的四类（三 seed 非加权平均；括号内为三 seed 合计的绝对查询数，
总计 4,122）：

| 类别 | 占比 | 计数 | 含义 |
|---|---:|---:|---|
| gold 从未进入 K=1000 池 | **48.10%** | 2,019 | 第一阶段表示失败，第二阶段无论如何都取不回 |
| 在池内，但 ≥10 个候选在两路信号上同时支配它 | **13.64%** | 549 | 任何单调融合都取不回，必须要第三路信号 |
| 在池内且可达，但现融合没取回 | **7.95%** | 322 | **Z 系列剩下的全部空间** |
| 命中（= `gold@10`） | **30.31%** | 1,232 | — |

补充统计：

- 池内 gold 中有 **11.4%（239 个）task prior 支持数为 0**，prior 对它们完全失明；这 239 个里只有 86 个
  最终被返回，靠的是 dense 分数和 tie-break。
- 池内 gold 在 (dense, prior k=5) 下的支配者数量分布：p50 = 2，p75 = 14，p90 = 81，p99 = 752，
  max = 998。**一半的池内 gold 只被 2 个候选支配**，几何上并不绝望；被卡死的是一条很重的尾巴。
- 被卡死的 gold，其在池内的 dense 排名 p25 = 92、p50 = 263、p75 = 538——它们不是"dense 也认为很好
  但被 prior 拖累"，而是两路信号都不看好。
- 549 个被卡死的 gold 里，397 个有 prior 支持、152 个没有。所以"补 prior 覆盖"最多只解决其中 28%。

## 5. 为什么 Z1/Z2 会失败：机制而不是运气

三条独立证据指向同一个解释。

1. **常数权重能拿的已经拿到了。** Z1 的 `beta=8, k=20` 把三 seed 均值从 0.3031 抬到 0.3142，占两信号族
   上界剩余空间（0.3827 − 0.3031 = 0.0796）的 14%；Z2 再加 0.0007。作弊 gate 也只能到 0.3555。整个族
   本身就窄。
2. **Z2 的 gate 特征方向对，但目标错。** gate 中位数 0.855 / 0.887 / 0.863 全部贴近常数 `g0 = 0.8889`，
   三个支持度类特征系数被单调约束优化器压到 0。§2.3 的分层表说明：失败集中在 **task 竞争者多**的查询上，
   而 Z2 的特征衡量的是 **prior 有多可信**。这两件事在本 benchmark 上几乎正交——热门任务的 prior 恰恰
   支持数最多、最"可信"，但同时也最难排。
3. **开发集不能选参。** validation 只有 347/548/732 个查询，难度分布与 test 不一致（§2.3 第 2 点）。
   在这种条件下，任何在 validation 上选出的单点配置都很难跨三个 test seed 稳定，Z1 的 seed 1 退化正是
   这个机制。要继续做第二阶段选参，必须先解决开发集，而不是先换模型族。

## 6. 剩余空间在哪里，按可得收益排序

### 6.1 第一阶段表示（最大，且是唯一能同时抬高所有天花板的东西）

全湖 dense 对 gold 的召回曲线（三 seed 均值）：

| K | 10 | 50 | 100 | 1,000 | 10,000 | 100,000 | 1,000,000 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `recall@K` | 0.1427 | 0.2814 | 0.3380 | 0.5188 | 0.6800 | 0.8423 | 0.9513 |

- gold 的全湖中位排名是 511 / 385 / 3,960。48.1% 的查询里，gold 排在 1,000 名之外。
- 在当前 58.4% 的吃进率下，`recall@1000` 每提高 10 个百分点，`gold@10` 大约提高 5.8 个百分点——**单这一
  项就超过整个两信号融合族剩下的全部上界空间（+0.080）**。
- 这一路的可辩护性也最强：Y2/Y4 已经证明 ANN 不是瓶颈（`recall@1000 ≥ 0.99` 对 exact），所以
  `recall@1000 = 0.5188` 完全是表示的问题，不是索引的问题。

### 6.2 第三路信号（唯一能突破 §3.1 上界的东西）

13.64% 的查询里 gold 被两路信号同时支配。要动它们，新信号必须**不是** dense 与 prior 的单调函数。
按本仓库已有证据，优先级最高的两条：

- **血缘 / 兄弟通道。** 冻结图里有 859,065 条 `is_base_of` 边、76,672 个 parent，28.5% 的模型有 parent，
  而当前第二阶段完全没有用到它。历史上 D0 与 X3 两次都测到 sibling 通道有可观增量。这是唯一一条既在
  图里、又与 (dense, prior) 正交、且服务时可 O(1) 查表的信号。
- **prior 覆盖的结构性缺口。** 池内 gold 有 11.4% 完全没有 prior 支持。用 `similar_to` 数据集邻居把
  prior 从 `task` 级推广到 `task ∪ 近邻数据集` 级，可以在不改表示的前提下给这批 gold 一个非零分数。
  注意上界：这条最多覆盖被卡死查询里的 28%。

两条都必须先在**独立开发集**上做 §3.1 意义下的上界核算——即"加入新信号后，三信号 Pareto 上界是否
显著高于 0.3827"——再决定要不要实现。这个核算不需要训练任何东西，成本是一次池扫描。

### 6.3 不值得单独做的

- **加大 K。** 单独做只值 +0.014（K=1,000 → 10,000），并且边际吃进率还在下降。只有在重排器先变强之后
  才值得重开。
- **再调融合权重／校准／门控。** 上界 0.3827，Z1+Z2 已经证明可实现且跨 seed 稳定的部分接近 0。
- **训练黑盒 residual ranker（旧版 Z0 方向三）。** 它仍然是 (dense, prior) 的函数，除非显式引入第三路
  特征，否则同样受 0.3827 约束；旧版设定的启动条件（gate 先证明互补性）也没有成立。

### 6.4 一个口径提醒

`gold@10` 是"历史观测到的最优模型是否进前十"。同一批查询上，接受与最优值相差 0.01 以内的
`gold-gap@10` 已经是 0.3484（三 seed 均值），root 宏平均 `gold@10` 是 0.2336。也就是说，
0.3031 与 0.3484 之间约 4.5 个百分点的差距是"近似并列"造成的度量效应，不是排序能力缺口。讨论提升空间
时不应把这部分算进去。

## 7. 可证伪命题与止损

Z 系列如果继续，只应回答一个问题，且必须先用上界核算而不是先训练：

> 在 K=1000 的冻结池上，引入血缘/兄弟通道（或数据集近邻推广的 prior）之后，三信号 Pareto 上界能否
> 从 0.3827 显著上升？

判据：

1. 先在独立开发集上算上界。若三信号上界相对 0.3827 提升不足 +0.03，**直接停止**，不实现任何打分器。
2. 若上界提升成立，才实现最简单的固定融合，并沿用 Z1/Z2 的预注册纪律：validation 选参、test 只跑一次、
   三 seed 均不下降、逐 seed `rescue > harm`、top-10 参数量中位数不超过 2 倍、端到端 p50 ≤ 5 ms。
3. 在此之前必须先修开发集：validation 查询数、难度分布与 test 的错配（§2.3）是 Z1 失败的直接原因，
   不修就换方向只会重复同一个失败。
4. 第一阶段表示的改进（§6.1）与 Z 系列并行、独立立项；它不受 §3.1 上界约束，是唯一能同时抬高
   0.3827 和 0.5190 两条线的工作。

对论文的直接影响：Z1、Z2 与本文都不进入正文，`gold@10 = 0.3031` 保持为最终数字。若正文需要一句关于
上限的话，可用本文的口径：**在固定 K=1000 的候选池上，任何 dense 与 task prior 的单调融合最高只能达到
0.3827，而完美重排器可达 0.5190；当前系统已经取得该池上限的 58.4%。**

§3.1 的上界与 §4 的四分解可用下面这段独立脚本重算（在 `ModelLakeFishing/` 下用本仓库 venv 运行）：

```python
import numpy as np, sys, os
sys.path.insert(0, os.path.abspath("..")); sys.path.insert(0, os.path.abspath("."))
from ModelLakeFishing.scale1m.baselines import fixed_tie_break

N = 3_016_439
key = fixed_tie_break(N); order = np.argsort(key, kind="stable")
tie = np.empty(N, np.int64); tie[order] = np.arange(N, dtype=np.int64)

for s in (0, 1, 2):
    p = np.load(r"D:/research/model_lake/data/data1m/metrics_z1/test_pool_s%d.npz" % s)
    ids = p["model"].astype(np.int64)
    dense = (p["dense_cos"].astype(np.float64) + 1.0) * 0.5
    PK = {k: p["prior_k%d" % k].astype(np.float64) for k in (1, 5, 20)}
    gold = p["gold"].astype(np.int64); nq = len(gold)
    gpos = np.array([(np.flatnonzero(ids[i] == gold[i])[0]
                      if np.any(ids[i] == gold[i]) else -1) for i in range(nq)])
    rows = np.flatnonzero(gpos >= 0)

    def top10(score):                       # 现融合 / 退化端点的实际命中
        out = np.zeros(nq, bool)
        for i in rows:
            j = gpos[i]
            out[i] = (((score[i] > score[i, j]) |
                       ((score[i] == score[i, j]) &
                        (tie[ids[i]] < tie[ids[i, j]]))).sum()) < 10
        return out

    def pareto(prior):                      # 严格单调融合的上界
        out = np.zeros(nq, bool)
        for i in rows:
            j = gpos[i]; d = dense[i]; q = prior[i]
            out[i] = (((d >= d[j]) & (q >= q[j]) &
                       ((d > d[j]) | (q > q[j]))).sum()) < 10
        return out

    union = (pareto(PK[1]) | pareto(PK[5]) | pareto(PK[20]) | top10(dense) |
             top10(PK[1]) | top10(PK[5]) | top10(PK[20]))
    hit = top10(dense + PK[5])
    print("seed %d  n=%4d  in-pool=%4d  hit=%4d  union-ceiling=%4d  pool-ceiling=%4d"
          % (s, nq, len(rows), hit.sum(), union.sum(), len(rows)))
```
