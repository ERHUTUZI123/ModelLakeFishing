## 2. 数据集侧特征

F4 只做了模型侧，`x_d` 是本阶段建的，沿用自 D0 起就没变过的三视图：

```
x_d (458) = [ e_name 64 (哈希, seed 43) ‖ e_card 384 (MiniLM) ‖ e_stats 10 ]
```

`e_card` 的文本由 `scale1m/dataset_descriptor.py::dataset_descriptor()` 生成，输入是 F1.5 匹配到的卡片
（`description` 截断 400 字符 + `task_categories` + `tags`），没匹配上的退到该函数自带的名字兜底。
18,729 个节点里 3,928 个（20.97%）用上了真实卡片，其余是名字文本；描述符平均 97.1 字符。

`e_stats` 的十列按 D0 的定义从监督边算：边数的 `log1p` 两列、权重的均值/标准差/最小/最大、
root 规模的 `log1p`、`gold_eligible` 标志，末两列留空（`has_content` 恒 0，content 视图本档不启用）。

`similar_to` 仍是在 `e_card` 上做 k=20 的余弦 KNN，18,729 × 20 = 374,580 条，与历史各档同一算法。

## 3. 三类边

**监督边**直接来自 F2 的 `supervision_merged.parquet`，247,803 条，与 F2 报告逐条相等。
两端在建图前先做存在性断言：引用了梯子里没有的模型或节点就直接失败，
因为 `edge_index` 指向不存在的行不会报错，只会索引到别处。实测两侧都是 0 个未解析。

**血缘边**用规范化 id 的 hashmap join，O(N)：

| 量 | 实测 | F1 预测 |
|---|---|---|
| 声明 `base_model` | 894,089 | 894,089 |
| 自指丢弃 | 2,008 | 2,008 |
| 湖内可解析（边数） | **859,065** | 859,056 |
| 解析率 | 96.083% | 96.08% |

比 F1 的预测多 9 条，原因可指认：F1 是在 3,003,759 条快照上算的，而梯子多出 12,680 个
只在历史监督里出现的模型，其中 9 个恰好是别人声明的 `base_model`，现在解析得到了。

`relation` 分布：finetune 325,400 / adapter 314,944 / quantized 167,522 /
merge 14,669 / 未声明 36,530。`r_mm'` 的离散有序权重因此有了真实输入。

度数分布仍是长尾（`lineage_stats.json`）：76,672 个不同父节点，每个父节点的子模型数
p50 为 1、p90 为 6、p99 为 118，**119 个父节点各带 1,000 个以上，最大的 `flux.1-dev` 带 43,346 个**。
28.479% 的模型有父节点。这组数与 F1 §7.1 的预测一致，也是 §8 里过平滑风险的量化形态。

| 门 | 判据 | 结果 |

契约检查需要一次全图前向，三百万节点在本机装不下，因此在**前 150,000 个模型的切片**上跑，
切片保持完全相同的目录布局与 `meta.json`。检查覆盖了字段完整性、`family_vocab` 的双射性、
五种边的存在与方向配对、以及梯度边界：两张 embedding 表拿到非零梯度、frozen `x` 没有梯度、
前向返回的模型行数等于节点数。全图前向本身由 F7 的分块推理承担，那里会真正跑满 3,016,439 行。

**这条门查出了一个真实缺陷。** 首次运行报 `family_vocab len (41055) == num_families (41056)` 不通过。
原因是写 `meta.json` 时用 `pd.read_csv` 读 `family_vocab.csv`，而词表里有两个字面量家族名
`"nan"` 与 `"null"`，pandas 默认把它们解析成缺失值并折叠成同一个键，词表因此少一行。
`family_vocab.csv` 与 `family_id.npy` 本身都是对的，错的只是读法。
加 `keep_default_na=False` 后重跑，41,056 行、id 是 `0..41055` 的连续双射，契约通过。

值得记下来的是：这个错误不会让任何一步失败，只会让 `nn.Embedding` 的行数与词表差一行，
而 `e_fam` 的行身份是 CLAUDE.md 里点名的三大风险之一。它是被契约检查抓到的，不是被眼睛看到的。

## 6. 划分的可复现性

用训练时将要调用的同一个 `make_root_aware_splits`，在同一张图上按三个 seed 各跑两次：

| split_seed | test 边（含负样本） | test 边集合 sha256 | 两次是否一致 |
|---|---|---|---|
| 0 | 99,174 | `20caf4734a280001…` | 是 |
| 1 | 101,782 | `235a28f8e47111ab…` | 是 |
| 2 | 103,358 | `1c2930fd2ef6568c…` | 是 |

划分按数据集节点的 root 分组，root 取数据集名的第一段（`glue/qqp` 与 `glue/sst2` 同根，
`nyu-mll/glue` 归到属主）。全图共 9,341 个 root。按属主分组比按数据集分组更保守，
方向上是防泄漏而不是制造泄漏。

`test_edges` 里含负样本（`neg_ratio=1.0`），所以它不是"测试查询数"，
查询集的口径在 F6/F8 由 harness 定义，这里只用来钉住划分的确定性。

## 7. 与计划的偏离

| # | 计划原文 | 实际 | 理由 |
|---|---|---|---|
| 1 | `verify_rung_graph --rung full` 全绿 | 自检写在 `build_graph_rf.py` 里，输出到 `GRAPH_REPORT.json` | 那个模块是为 100K 档写的，硬断言 9,603 个数据集节点等常量，对本档无效。五条判据等价迁移 |
| 2 | `check_stage2_contract --sharded` 在全图上跑 | 在 150,000 个模型的切片上跑 | 全图前向需要的内存本机没有；切片保持相同布局，覆盖同样的检查项。全量前向由 F7 的分块推理承担 |
| 3 | 计划未提 `x_d` 由谁构建 | F5 建 | F4 只做模型侧；`e_stats` 依赖监督边，必须等 F2 合并完成 |

另有两处实现缺陷在本阶段被发现并修复，都是同一个根因——pandas 的缺失值语义：
`description` 为空时是 NaN 而 `NaN or ""` 仍是 NaN（导致描述符生成崩溃）；
`relation` 为空时同理，标签写成了字符串 `"nan"`（`relation_id` 映射正确，只是统计标签错）。
两处都改用显式的 `pd.isna` 判断。
