# A0.7 reporting-unit correction

The original A0.7 inventory declared `percent` for six retrieval ratio/coverage metrics but stored their native fractional values. For example, `retrieval_diagnostics.exact_pool_retention.mean` had historical94.32 and new0.9353648304; subtracting those numbers mixed units. Correct presentation is new93.53648304%, with approximately−0.78351696 percentage points relative to the published94.32%.

`scale1m/recompute_a0.py` now keeps the scientific `new_measurements` fraction unchanged with explicit `unit="fraction"`. It converts once at the inventory boundary to the declared `percent`, records raw unit/conversion factor, computes old/new differences in the same unit and marks percent differences `percentage_points`. Source percentages already expressed as percent retain their values and gain explicit `unit="percent"`. Seed summaries retain the raw unit; missing/undefined statuses and null values retain their meaning. Markdown percent rows carry a `(%)` label. The report also records hashes of both active independent reader source files.

Scope of edits: the reporting reader and its tests. Raw evaluator outputs, graph, embeddings, candidates, priors, query identities, protocol, frozen inventory and source recount are unchanged. All scientific per-seed metrics and raw fractional summaries are invariant. The parent preserved the original reports under `before_library_update_results/` and original producer source files under `frozen_checkout/` before applying this correction.

Validation: the complete `test_recompute_a0.py` module passed39tests. Six new cases cover the real frozen percent inventory/historical94.32 value, unequal seed ratios, six ratio values derived from raw tiny-pool fixtures, already-percent source statistics with and without a unit tag, missing/undefined results, preservation of frozen bytes and active reader hashes. The final filtered rerun passed7tests (the six new cases plus the existing timing-percentiles test). Exact commands, timings and changed-code hashes are recorded in `UNIT_CORRECTION_TESTS.json`.
