## 3. 实现边界和核对出的差异

训练的 40 个有效配置键与 A0.1 冻结配置逐键相同；初始化种子、split seeds、25 epoch、损失、采样、图关系、维度和最终系统参数保持原规则。接口检查见 [A0_INTERFACE_CHECKS.json](A0_runs/A0_2/A0_INTERFACE_CHECKS.json)。

1. **精确参照的同分排序。** 原 full-fused top-10 的 `torch.topk` 在同分边界可以选择与排名计数不同的 ID。A0 使用既有、与标签无关的固定 tie 顺序保存 full-fused top-10；legacy 模式保留原行为。
2. **精确参照的浮点归约。** 小型 128 维同向量 fixture 复现：原 probe 逐元素求和与全库分块 GEMM 的 float32 舍入不同，可能让保存 top-10 与排名计数矛盾。A0 probe 改为读取相同形状分块 GEMM 的值。float32、公式和阈值不变，没有容差排序或分数舍入。精确参照会增加涉及 probe 的分块 GEMM 成本，计入离线计算。新旧 exact 差异也受该一致性修正影响，不能全部归因于七列特征修复。
3. **哈希绑定。** 新图不仅重算文件表，也把编码元数据指纹放进被绑定的修复报告。训练、导出和 prior 入口识别 A0 标志及修复文件，最终图 digest 固定，防止误用旧图或不完整图。
4. **生产记录。** 正式 A0 训练记录、导出 manifest、sidecar 和评测原始文件绑定 run、seed、新图及末 epoch checkpoint。新增耗时、资源和原始数组哈希记录服务于全指标复算，未改变训练或检索公式。训练段沿用 `train_eval_one` 的边界，包含设置、训练/checkpoint 和既有训练后 test/full 评估；RSS 是进程生命周期峰值，续跑逐段保存实际环境。exact/full 与 exact1000 共享计算区间，完整成本只计一次。
5. **效果门。** A0 记录实际效果判定，即使下降也完成固定 K=1000 的测量。ef 按 `1000/1500/2000/3000/5000` 顺序到首个 ID recall≥0.99；全失败则记录失败并在 5000 完成测量。未访问 ef 标为 `not_applicable`，没有把失败改成通过。
