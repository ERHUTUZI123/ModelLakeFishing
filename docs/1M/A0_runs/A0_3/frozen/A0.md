## 4. 唯一的模型输入修复

事实文档 §3.5 给出的原统计块为：

```text
[log(1+n), log(1+n), mean, std, min, max, log(1+root_node_count), gold_eligible, 0, 0]
```

其中观测数量、性能分布统计和资格标记依赖性能记录。新图对**所有数据集节点**统一使用：

```text
[0, 0, 0, 0, 0, 0, log(1+root_node_count), 0, 0, 0]
```

在 `x_dataset` 的零基列索引上，对应：

```python
x_dataset[:, 448:454] = 0.0
x_dataset[:, 455] = 0.0
```

- 保留列 454 的冻结 root 节点数，它来自节点表；保留原本为零的 456、457。
- 不删列、不调整输入层大小；`458 → 486 → 128` 保持不变，使参数形状、初始化布局和其余输入可以直接对照。
- 原名称、MiniLM、模型特征、词表、categorical IDs、节点 ID、边端点、边权和 graph surgery 规则保持一致。
- `gold_eligible` 继续留在独立评估表中选择查询；held-out 性能记录继续作为计分标签。不能因为屏蔽输入列而修改测试资格、gold 或监督权重。
- 在新的图构建产物中直接生成这七个零列。不能只在测试时清零，也不能仅在训练入口遮盖、导出时又读回旧值。
- 正式模型全部从 epoch 0 开始训练，不加载旧模型权重、optimizer state 或旧 smoke checkpoint。

这个修改解决已确认的性能统计输入通道。保留原来的 materialized-node、root-aware 评估范围，不将其扩大为全新数据集的 inductive 检索验证。

## 7. “全部指标重新计算”的逐项合同

### 7.1 质量、coverage 与位置

对最终 HNSW top-1000 + prior 系统的三个 seed 全部计算：

| 指标 | 定义 / 必须保存的输入 |
|---|---|
| queries、roots、N、K、return size | 从当前实际 row maps、计分查询和输出统计，不抄旧数字 |
| gold@1 / gold@10 | 同一个原规则确定的历史 gold 是否在返回第 1 / 前 10 名 |
| top3@10 | 历史前三中的任意一个进入最终前 10；不是三者全部召回率 |
| gold-gap@10 | 最优历史值 0.01 范围内的任意模型进入前 10 |
| root-macro gold@10 | 先在每个 root 内平均，再对 root 等权平均 |
| median reranked gold position when retrieved | gold 进入实际 1000 候选池的查询中，其完整重排位置的中位数；须保存完整 pool，不能只靠 top-10 文件 |
| actual HNSW gold coverage@1000 | gold 是否出现在实际 HNSW 候选池；与 exact coverage 分开 |

事实文档没有给出某字段的旧值时，表中写“未报告”，仍计算新值。
若原计分函数输出其他 gap/root 分项或统计，也保存并汇总，不因原 summary 未列出而丢弃。
不存在全库总排序的最终输出不能填写“全库 median gold rank”；只报告上述条件中位数和条件查询数。

对于没有召回 gold 的查询，gold@1/10 均为失败，查询仍留在分母中。
“gold 已召回时的中位数”使用自己的条件分母，不能拿条件命中率替代全查询命中率。

### 7.2 ANN 与精确参照

对新 exact full lake、新 exact top-1000 和新 HNSW top-1000 使用相同查询与融合器计算质量。
按 seed 保存未舍入值，再计算：

```text
exact pool retention_s = gold10_exact1000_s / gold10_full_s
ANN retention_s        = gold10_hnsw1000_s / gold10_exact1000_s
overall retention_s    = gold10_hnsw1000_s / gold10_full_s
```

三 seed 保留率取逐 seed 比值的算术平均，不能用两个跨 seed 均值相除代替。
分母为零时显式标记 undefined，并保留分子分母，不填 0 或 100%。

此外重新计算：每个 ef 的 `recall@1000`、选中 ef、exact gold coverage、full-fused top-10 在 exact dense top-1000 的成员覆盖率。
保留率和 coverage 的每个分子、分母都必须来自 A0 产物，不能出现“新 numerator / 旧 denominator”。

### 7.3 成本与训练记录

- 新 HNSW 建立的 `build_seconds`、每份 `index_bytes` / GiB、三份总字节；字节数直接读取文件。
- HNSW、prior lookup + rerank、两者合计的 p50 / p95，逐 seed 保存原始逐查询时间。
- 合计分位数从每个查询的合计耗时计算，不能把两项 p50 或 p95 相加。
- 三 seed 均值按旧表的“逐 seed 分位数再取平均”口径；若另报合并分布分位数，必须独立命名。
- 训练、导出、prior 构建、exact 参考计算和完整评测耗时重新计时；训练 loss、epoch 数、初始化种子、配置与资源峰值由本轮日志生成。
- 若发生合法续跑，总成本汇总所有分段；最后一次启动的 wall-clock 不能代表 25 epoch 总训练时间。
- 增加的资源观测若事实文档无旧值，标记“旧值未报告”，不从其他 FXYZ 记录补作权威旧值。

原配置明确禁用的训练诊断保留 `disabled` 及原因。因为中断尚未计算的指标标为 `missing`；二者不能混用。

### 7.4 自动完整性检查

`A0_METRIC_INVENTORY.json` 每项至少包含：

```text
name, scope, seed, definition, unit, aggregation,
old_value, old_source_section, old_display_precision,
new_value, recomputed_from, artifact_hashes, status
```

要求最终系统所有必需项的状态为 `recomputed`；固定协议参数为 `verified`；数学上无定义的值为 `undefined` 并说明原因。
逐 seed 的缺失值不得被 mean 自动跳过；三个 seed 齐全才产生对应三 seed 汇总。
4,122 是三个 split 下查询观察次数的总和，不宣称为 4,122 个互不重复的新数据集。

旧 reference 与新 measurements 使用独立对象保存。旧 JSON 只能供旧值对照；禁止复制旧报告后局部覆盖、保留遗留数值。

每个 seed 两份全模型 128 维 float32 导出（full/eval）约为 `2 × 3016439 × 128 × 4` 字节，
另加索引、图、checkpoint、精确池和日志。磁盘预算按实际所需文件计算，明确区分冻结输入共享和新生成产物。

| 情况 | 处理 |
|---|---|
| 源数据/row map/hash 与协议不一致 | 停止受影响阶段，定位差异；不得改 query 集凑分母 |
| 性能输入列仍有非零值、test root 进入 prior | 修复后重建受影响图/模型及全部下游产物 |
| 模型训练出现 NaN/Inf、checkpoint 损坏 | 保存失败证据，解决原因后从同一有效 A0 checkpoint 续跑或重启该 seed |
| 新结果低于旧值 | 完成三个 seed 和全部指标，报告下降；不加 epoch、不改先验或 K |
| ef 网格没有达到 0.99 | 记录完整 trace 和失败状态，按 §6 的预设处理完成测量，不假称达到原标准 |
| 某成本指标无法测量 | 记录缺失原因，任务保持该项未完成；不得填写旧值代替 |
| 中途代码或源文件变化 | 核验影响；正式运行需绑定同一实现。影响计算的变更要求重跑受影响 run |
