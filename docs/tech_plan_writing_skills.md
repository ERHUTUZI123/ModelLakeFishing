# 说人话的技术报告

这个 skill 的目标只有一个：让技术报告读起来像一个**懂行的人在跟同事解释**，而不是像一份急着证明自己很牛的 PPT。

中文技术写作里有一类通病：为了显得有分量，把普通的东西套上一层"战略感"的壳。读者要花力气把壳剥掉才能拿到里面那点信息。好的技术报告应该反过来——信息密度高，包装为零。

## 核心判断：这句话是在传递信息，还是在营造气氛？

写每一句之前问一遍。如果一句话删掉之后，读者对"要做什么、为什么、怎么验证"的理解没有任何损失，那它就是气氛，删掉。

**营造气氛的典型信号（看到就改）：**

- 给普通的东西起战略绰号：把"精度"叫"A 轴"、把"延迟"叫"头号交付物"、把"三条纪律"叫"三铁律/三不原则"、把"技术优势"叫"护城河"。绰号不传递信息，只制造"这很重要"的暗示。直接说"精度""延迟"就行。
- 情绪性形容词冒充结论："质变""碾压""断链""塌了""兑现""还清了十个月的债"。这些词在描述**你的感受**，不是描述**发生了什么**。把感受换成事实：不是"质变"，而是"1M 湖里约 95% 模型没有性能记录，冷启动从一个小切片变成全局"。
- "立意""这一阶段唯一要证的事""一句话"这种给自己加戏的结构标题。读者不需要被告知"接下来这段很关键"，把关键内容写清楚就行。
- 用排比和加粗堆气势："**在真实的 10⁶ 模型湖上实测这条曲线，并证明精度轴在 83× 干扰项冲击下不塌**"——这句话真正说的是"在 100 万模型上实测延迟曲线，并检查精度掉多少"。

**真正在传递信息的句子长这样：**
- "N 从 1.2 万加到 100 万，看检索延迟怎么变。"
- "对比损失现在是 O(N²)，1M 上会 OOM，改成负样本采样。"
- "HALO 模型的标签不进训练，这样 N 是唯一变量，曲线才解释得通。"

## 具体改写对照

| 伪生动 | 说人话 |
|---|---|
| B 轴：延迟（头号交付物） | 延迟（这一阶段最重要的产出） |
| 把「亚线性护城河」从外推变成实测 | 之前亚线性扩展只有 12K 的曲线加外推，这次在 100 万上实测 |
| 三个不能违反的纪律 | 三条要守住的原则 |
| 这是全新的、12K 上不存在的结论 | 这个结论 12K 规模上做不出来 |
| 在审稿人眼里是两个物种 | 审稿人会把外推和实测当成两回事 |
| 10 个月的硬件债还清了 | 卡了 10 个月的 30K 全量训练终于能跑了 |
| 质变 / 碾压 / 塌 | （直接描述数字变化，不用这类词） |
| 立意：这一阶段唯一要证的事 | 目标 |
| 一个关键的好消息 | （直接说那件事，好不好让读者判断） |

## 保留什么

**不要矫枉过正**。技术报告该有的东西一样不少：

- **精确的技术术语**照用。"O(N²)""HNSW""负样本采样""held-out""OOM""扇出上限"——这些是真信息，不是包装。区别在于：术语指向一个具体的技术事实，绰号只指向"这很重要"的感觉。
- **数字、量级、条件**是报告的主体，越具体越好。"1M × 9603 × 4B = 38.4 GB，直接死"比"内存会爆"好，因为它可复核。
- **风险和失败**要写。哪里会 OOM、哪个是关键路径、哪一步不做整个计划作废——这些是最有价值的部分，别为了显得顺利而弱化。
- **结构**（分阶段、分优先级、验收标准、决策登记）该有就有。问题从来不是"有结构"，而是给结构起浮夸的名字、加抒情的过渡。

## 语气

写得像你在跟一个水平和你相当的同事讲，他没时间读废话，但你也不需要向他证明什么。

- 不用感叹号强调重要性，靠内容本身。
- 该下判断就直接下："这条路走不通，因为 X。"不要"这或许暗示着一种可能性"。
- 不确定就说不确定，给区间、给条件，不要用肯定的语气掩盖没实测的事实。原报告里"实测"和"外推"必须分清，这个纪律本身是对的——问题只在于别把它包装成"消灭审稿人唯一攻击面"。
- 中英混搭是自然的，技术词该用英文就用英文（HNSW、embedding、OOM），不用硬翻成"分层可导航小世界图"。别的地方用正常中文。

## 一个自检清单

写完之后扫一遍，命中任何一条就改：

1. 有没有给普通概念起战略绰号（X 轴、护城河、铁律、头号 XX）？
2. 有没有情绪词冒充结论（质变、碾压、断链、还债、塌）？
3. 有没有"接下来这段很重要"式的加戏标题（立意、唯一要证的事、一句话）？
4. 有没有为了气势而堆的排比 + 满屏加粗？
5. 删掉这句话，读者会少知道一件具体的事吗？如果不会，删。

改完的标准不是"变短了"，而是**每一句都在说一件读者能复核的具体事**。
