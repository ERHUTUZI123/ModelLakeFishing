请修改当前的 `Retrieval-Quality Remediation Plan`，保留现有数据、Track A–E 框架和两阶段系统，但重新调整方案的主叙事、优先级、指标和验收标准。

我们进一步分析后发现：

* 实际模型池确实是 2,000，因此 uniform random 的 (K/2000) 计算没有错误。
* 但 61 个查询的 top-500 平均 pairwise overlap 达到 57.6%。
* 一个完全不看查询、对所有 dataset 返回同一份模型排名的 static global ranking，已经能达到：

  * gold@10 = 0.016
  * gold@200 = 0.295
  * gold@500 = 0.656
* G2 对应为：

  * gold@10 = 0.230
  * gold@200 = 0.656
  * gold@500 = 0.869

这说明 G2 确实学到了 query-conditioned signal，但 moderate-K recall 中有很大一部分来自 dataset-independent global popularity。`top-200 + reranker` 有工程价值，却只能作为 containment 和 serving improvement；长期核心应放在 Stage-2 graph training，尤其是恢复 (z_d) 的 dataset conditioning。

请按下面要求修改方案。

## 1. 修改整份方案的核心结论

当前结论：

> fix precision above the index fast, fix geometry below it durable

可以保留，但需要明确主次：

* Track B/C 是 serving containment、诊断工具和短期效果来源。
* Track D 是主要研究方向和长期质量来源。
* 扩大 (K) 不能被描述为 embedding 已经完成了 recall 工作。
* reranker 能处理候选集合内部的排序，无法解决候选集合跨 query 高度重复、专门化模型未被召回的问题。
* 当前核心故障应表述为：

  1. query-independent popularity 占据了大量 recall；
  2. (z_d) 对不同 dataset 的条件化不足；
  3. hubness 是上述条件化不足与训练分布偏差共同产生的结果。

请避免把“index 负责 recall”写得过于简单。HNSW fidelity 已经是 1.000，所以：

* HNSW 的责任是忠实保留 exact-cosine neighbors；
* embedding geometry 决定 semantic candidate recall；
* reranker决定候选集合内部的 final precision。

架构图建议修改为：

```text
dataset features
      ↓
query-conditioned z_d geometry
      ↓
exact cosine / HNSW top-K
      ↓
metric-aware reranker
      ↓
top-10
```

并在图中标注：

* HNSW preserves learned ranking;
* Stage-2 training determines candidate quality;
* reranker improves ordering only within retrieved candidates.

## 2. 强化 Track A：加入“条件化能力”指标

Track A 除了现有 gold@K、median rank、hub occupancy 和 ANN recall，还必须固定输出以下指标。

### 2.1 三列基线必须在所有报告中并排出现

每个 (K\in{10,50,100,200,500}) 都报告：

1. uniform random (K/N)
2. static global ranking
3. per-dataset G2 ranking

禁止只拿 G2 与 uniform random 比较，因为 static ranking 才能测量 dataset-independent popularity 已经解释了多少结果。

### 2.2 新增 conditioning gain

定义：

[
\text{conditioning gain@K}
==========================

## \text{G2 gold@K}

\text{static gold@K}
]

同时报告归一化版本：

[
\text{normalized conditioning gain@K}
=====================================

\frac{
\text{G2 gold@K}-\text{static gold@K}
}{
1-\text{static gold@K}
}
]

这个指标应成为 Track D 的主要 KPI 之一。Graph training 的目标不仅是提高 gold@K，还要提高相对于 static ranking 的 query-conditioned gain。

### 2.3 新增候选集合条件化指标

至少报告：

* mean pairwise top-K overlap
* top-K Jaccard overlap distribution
* candidate occupancy concentration
* effective candidate diversity 或 occupancy entropy
* 每个 query 相对于 static top-K 的新增候选比例

这些指标用于检查不同 dataset 是否真的得到不同的候选集。

单独增加 distinct models 数量不够，因为随机扰动也可以增加多样性，却未必增加相关性。

### 2.4 区分两类 recall

报告中明确分开：

* ANN recall：HNSW 是否复现 exact cosine top-K；
* semantic gold recall：embedding ranking 是否包含 gold。

不要把两者都简称为 retrieval recall。

### 2.5 尽量补充 clean-protocol gold@K

当前 gold@200 和 gold@500 主要来自 optimistic full-graph replay。

Track A 应尝试在 clean fixed split 上补充：

* clean gold@50
* clean gold@100
* clean gold@200
* clean gold@500

如果实现成本较高，至少要在所有表格中明确区分：

* clean promotion metrics
* optimistic replay diagnostics

Replay 数字不能直接成为长期 promotion threshold。

## 3. 重新定位 Track B

将 Track B 的标题或说明改成：

> Serving-time containment and instrumentation

保留：

* K=200 default
* K=500 max
* CSLS ablation
* occupancy sidecar

但请修改论证。

### 3.1 K=200 的依据要同时展示 static baseline

当前写法主要用：

[
\text{G2 gold@200}=0.656
]

支持 K=200。

需要同时写明：

[
\text{static gold@200}=0.295
]

所以 G2 在 top-200 确实提供了显著 query-conditioned uplift，但 0.656 仍然是 optimistic replay，K=200 只是让 reranker 获得可操作候选集。

### 3.2 K=500 只作为高召回模式

说明：

* G2 gold@500 = 0.869；
* static ranking 已达到 0.656；
* top-500 平均重叠率为 57.6%；
* 扩大到 500 会引入大量 query-independent candidates。

所以 K=500 不应成为默认 serving 配置，除非 latency budget 和 reranker throughput 允许，并且 clean protocol 证明额外候选确实带来 end-to-end 收益。

### 3.3 occupancy sidecar 防止 evaluation leakage

如果 `hub_occupancy` 要成为 Track C 的输入特征，必须说明它如何计算：

* 训练 reranker 时，只能使用训练侧或允许的 serving-query statistics；
* 不能使用完整 evaluation dataset 集合计算 occupancy 后再作为测试输入；
* 使用所有测试 query 计算出的 occupancy 只能用于报告和诊断。

请把这一点写入 Track B/C 的 methodology。

## 4. 重新定位 Track C

当前标题：

> Stage-4 metric-aware reranker (the designed fix)

力度过强。

建议改为：

> Stage-4 metric-aware reranker: containment, diagnosis, and final-stage precision

强调：

* reranker 是最终系统可能长期保留的一层；
* 现阶段它也承担诊断作用；
* 它无法恢复未进入 top-K 的模型；
* 它无法让高度重复的候选集合产生真正的 dataset-specific recall；
* 它的成功不能证明 embedding geometry 已经解决。

Track C 需要新增以下评测。

### 4.1 报告 conditional reranking success

除了最终 gold@10，还报告：

[
P(
\text{gold enters reranked top-10}
\mid
\text{gold exists in retrieved top-K}
)
]

这个指标衡量 reranker 对“可救回查询”的利用能力。

### 4.2 同时报告 end-to-end ceiling

明确：

[
\text{reranked gold@10}
\le
\text{retrieval gold@K}
]

将以下两类失败分开：

* retrieval miss：gold 未进入 top-K；
* reranking miss：gold 已进入 top-K，但未进入最终 top-10。

### 4.3 增加 static-candidate ablation

建议增加一个诊断对照：

* 在 static global top-200 上训练/评测同一个 reranker；
* 在 G2 per-query top-200 上训练/评测 reranker。

如果两者差距很小，说明 reranker 主要依赖 global candidates 和 metadata，G2 conditioning 贡献有限。

如果 G2 candidates 明显更好，说明 embedding 中存在可利用的 dataset-specific signal。

### 4.4 调整 Track C 的成功表述

`replay gold@10 ≥ 0.40` 可以继续作为 directional target，但不要把它写成整个系统“修复完成”的证明。

Track C 的核心验收应包括：

* reranked gold@10 提升；
* conditional reranking success 提升；
* observed metrics 无明显下降；
* G2 candidates 明显优于 static candidates；
* 不依赖 evaluation-derived occupancy feature。

## 5. 提高 Track D 的优先级并重新排序内部工作

Track D 应成为方案的主战场。

建议把 Track D 内部顺序调整为：

### D.1 Metadata enrichment

保留现有内容：

* 修复 task_type `Other`
* 扩大 incompatibility pools
* 用相同 G2 配置重新训练，形成控制实验

### D.2 Dataset-side conditioning repair

把当前的 dataset-side conditioning 从第三项提升为第二项。

依据包括：

* (z_d) intrinsic dimension 约为 2；
* top-500 平均 overlap 为 57.6%；
* static global ranking 已经能达到 gold@500 = 0.656；
* 不同 dataset 的候选集合区分度不足。

这一项应被描述为最直接对应现有证据的 geometry intervention。

候选方向可以包括概念层面的：

* 增强 dataset metadata encoder；
* 显式编码 task、domain、modality、language、label semantics；
* 加入 dataset discrimination 或 spread objective；
* 防止 (z_d) collapse 到低维 cone；
* 增加跨 dataset 的 contrastive separation；
* 让相似任务靠近，同时让任务不兼容的数据集保持可分性。

无需在计划中锁定单一实现，但要明确每个实验必须测：

* intrinsic dimension / participation ratio
* pairwise top-K overlap
* conditioning gain@K
* gold@K
* hub occupancy
* clean five-metric results

### D.3 Hub-corrective objectives

将 hub-aware negative sampling、occupancy weighting、whole-model masking 等放在 dataset conditioning 之后。

原因是简单压制 hubs 可能只增加结果多样性，未必增加 query relevance。CSLS 已经展示了这个风险：

* distinct models 增加；
* gold@10 没有改善。

所以 hub correction 的验收不能只看 occupancy 下降，还必须要求：

* conditioning gain@K 上升；
* gold@10 或 gold@200 上升；
* static-vs-query gap扩大；
* clean metrics 通过 promotion rule。

### D.4 联合实验放在单因素 ablation 后

先逐项测试：

1. richer metadata
2. dataset-side conditioning
3. hub-aware negatives/objectives

再测试组合方案。

继续遵守 one change per row，避免无法归因。

## 6. 修改 sequencing

当前 sequencing 将 Track C 描述为“biggest expected win”，会让整个计划看起来依赖 reranker。

建议修改为：

```text
week 1        Track A: measurement and baselines
              Track B: K=200 containment + safe occupancy sidecar

week 1–2      Track D.1: metadata enrichment and controlled G2 rerun

week 2–3      Track D.2: dataset-side conditioning experiments
              Track C: reranker v1 in parallel as serving/diagnostic layer

following     Track D.3: hub-aware objectives
              Track C refinements based on better checkpoints

background    Track E: better-labeled lake
```

说明 Track C 与 Track D 可以并行，但研究优先级应指向 Track D.2。

## 7. 修改 gates

### R-2

当前：

> recall(gold ∈ top-200) ≥ 0.65 maintained on every promoted checkpoint

这个阈值来自 optimistic replay，不宜直接作为严格 promotion gate。

建议改为：

* clean gold@200 不得显著下降；
* replay gold@200 作为诊断指标；
* conditioning gain@200 不得下降；
* static-vs-query gap 必须报告。

### R-3

保留 reranker 的 clean full2k_gold@10 gate，同时加入：

* conditional reranking success；
* G2-candidate reranker 必须优于 static-candidate reranker；
* retrieval miss 与 reranking miss 分开报告。

### R-4

当前只要求：

* promotion rule pass
* max occupancy < 200/362

这个阈值可能被“打散结果”轻易满足。

请改成联合 gate：

* clean promotion rule pass；
* max occupancy 下降；
* pairwise top-K overlap 下降；
* conditioning gain@K 上升；
* gold@K 不下降。

Hub diversity 只能作为辅助条件，不能单独代表 geometry 改善。

### 新增 conditioning gate

增加一条专门衡量 dataset conditioning 的 gate，例如：

> relative to the static global ranking, the promoted checkpoint must increase conditioning gain at one or more primary K values without reducing clean gold metrics.

不必现在给出武断的固定数值，可在 Track A 产出多个 checkpoint 的分布后设定阈值。

## 8. 修改最终叙事

整份计划最后需要形成以下结论：

1. HNSW 系统层工作正常，它忠实复现当前 embedding ranking。
2. G2 明显优于 uniform random，也明显优于 static ranking，因此它包含真实的 dataset-conditioned signal。
3. 这部分 signal 仍然被 global popularity 和高候选重叠严重稀释。
4. K=200 + reranker 能改善近期 serving，并提供有价值的诊断实验。
5. 长期质量上限由 Stage-2 embedding geometry 决定，当前最有证据支持的方向是增强 (z_d) 的 dataset conditioning。
6. 去 hub 的目标应服务于相关性和条件化，不能只追求更多不同模型进入 top-10。
7. 最终系统可以继续采用两阶段结构，但研究贡献应集中在如何让第一阶段产生真正 query-specific、high-recall 的候选集合。
